Each implementation technology sits at a specific Tobari boundary. Go owns the
host CLI and validated orchestration. Docker realizes process, network, and
mount boundaries. mitmproxy and its Python addon enforce the HTTP/TLS flow,
while OPA and Rego decide generic effects.

This implementation-oriented page follows the product flow through [State and
recovery](/how-it-works/state-and-recovery/) and is optional for ordinary use.

## Technology follows the trust boundary

### Go CLI

The public `tobari` executable owns canonical path selection, domain
validation, effects and mutation contracts, application use cases, host state,
Docker orchestration, deterministic rendering, and the public command Catalog.
It passes one cancellation context through bounded adapters and keeps
credential-bearing values inside the Workspace-owned agent home.

### Docker Engine and Docker Compose

Docker Engine supplies runtime containers, read-only/read-write mounts, users,
capability drops, read-only root filesystems, resource limits, internal
networks, labels, volumes, and process execution.

Docker Compose owns only the shared Gateway and OPA services, shared networks,
and CA volumes. Per-Workspace containers and networks are reconciled by the
runtime adapter because their exact root/Workspace Template identity and lifecycle are
application concerns. Docker is trusted infrastructure; “runs in a container”
is not itself a security argument.

### mitmproxy Gateway and Python addon

Mitmproxy supplies transparent HTTP/TLS interception, streaming hooks, and
upstream TLS. Tobari's Python addon adds product-specific principal lookup,
body-free OPA input, fail-closed result validation, DNS address
classification/pinning, and audit. Gateway owns enforcement; it does not embed
policy interpretation or Workspace state storage.

### OPA and Rego

OPA is the shared policy decision service. Rego expresses Workspace Template
policy ceilings, default deny, exact learned allow/deny rules, and request
metadata constraints. OPA receives no request body or credential value and has
no egress interface.

### Local OCI image boundaries

Gateway, OPA, the mitmproxy build base, and the agent-ready base are OCI image
boundaries. Upstream inputs use immutable digests recorded in embedded version
metadata; Tobari-managed images use source-derived local tags plus inspected
local digests. No moving `main` or `latest` tag is runtime authority.

The current exact versions and digests are generated in [Component
versions](/reference/component-versions/) from `go.mod`, `versions.env`, and
runtime metadata rather than copied into this page.

## From editable source to runtime image

<ConceptDiagram name="image-supply" />

Gateway has one editable canonical public source tree under `gateway/`. The
CLI embeds a runtime snapshot under `internal/infra/runtimeassets/assets/`.
Byte-for-byte drift checks reject a changed snapshot that does not match the
canonical source. The embedded assets also include Compose, OPA policy, runtime
entrypoints, image identities, and license material.

CI validates multi-architecture OCI construction from canonical sources with
cache-only output. Normal runtime builds or reuse verify inspected digests and
component contracts. Image validation receives no package-write permission,
and Tobari has no OCI publication workflow.

## Concrete request mapped to technologies

For one allowed HTTPS call:

1. **Go** has reconciled the Workspace's Docker network, exact endpoint
   registry, CA, DNS setting, and Gateway/Workspace network guards.
2. **Docker/Linux networking** prevents direct egress and delivers TCP to
   Gateway's transparent ingress.
3. **Mitmproxy** terminates TLS A and exposes request headers to the addon.
4. **Python Gateway addon** derives the source-bound principal and posts schema
   1 input without body or credential values.
5. **OPA/Rego** returns allow or deny.
6. **Mitmproxy** establishes verified TLS B and streams the allowed request.
7. **Docker logs** retain bounded secret-free audit evidence for host-side Go
   review.

No one technology implements the complete promise.

## Failure behavior

- Missing/incompatible runtime or service image fails validation before unsafe creation.
- Digest/label/API/user/entrypoint mismatch fails closed.
- Canonical source and embedded snapshot drift fails repository checks.
- Invalid Rego or an incomplete aggregate fails before activation.
- OPA outage produces a closed Gateway response.
- Docker/host outage removes the enforcement substrate; Tobari does not claim protection under its compromise.

## Guarantees and limitations

**Guaranteed by contracts and tests:** fixed component roles, immutable normal
service identities, byte-checked canonical source snapshots, no OPA egress,
exact Compose topology, and preflight of runtime compatibility.

**Not guaranteed:** that an image digest alone makes code safe; isolation after
Docker/kernel/host compromise; provenance of a user-selected custom image;
availability of GHCR or external registries; or security review of arbitrary
tools installed by a custom runtime recipe.

## Summary

Tobari's behavior is a composition: Go interprets the task, Docker enforces
process boundaries, Gateway enforces the network path, OPA decides, and
content-addressed images make the runtime reproducible.
