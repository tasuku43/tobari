A **Workspace Manifest** is the reusable desired definition. A **Workspace** is
the durable instance bound to one canonical project root and one stable
Workspace Manifest ID. The **cluster** is shared enforcement infrastructure.
A runtime container is a replaceable observation of one Workspace.

## Identity and authority

A Workspace keeps:

- a generated stable internal Workspace ID;
- its canonical host project root;
- the stable `workspace_manifest_id` selected at creation;
- Desired/Next entry identity;
- the last successful `AppliedEntry`; and
- bounded last-failure and adoption state.

Internal schema protocols may retain `project_id` and predecessor `workspace_manifest_id`
wire names. They do not make display names or generation authoritative.
Workspace Manifest authority is its stable ID plus semantic digest;
`manifest_generation` is correlation only.

## Desired, applied, and observed

```text
Workspace Manifest revision (Desired / Next)
                 |
                 | explicit Workspace entry
                 v
Workspace AppliedEntry (Current / last success)
                 |
                 | read-only observation
                 v
container, network, attachment, health
```

Tobari has no resident controller. Only explicit Workspace entry and
`cluster up` are reconciliation boundaries. `status`, `list`, and `manifest
show` observe state without mutation. A failed reconciliation records failure
without replacing the last successful AppliedEntry. An attached Workspace
remains adoption-pending rather than being replaced underneath a session.

## Selection from the current directory

Tobari canonicalizes the host CWD before state or Docker work.

1. An exact indexed root under the explicit or default Manifest can be reused.
2. Indexed ancestor Workspaces are presented nearest-first for explicit choice.
3. The user may select one, create at the exact CWD, or cancel.
4. Tobari never creates a nested Workspace implicitly.

The omission default is selected with:

```sh
tobari manifest default set --name review
```

It changes no existing Workspace and performs no reconciliation. Use
`--manifest review` to choose explicitly without changing the default.

## Same root, different Manifest

The same canonical root can have distinct Workspaces under different stable
Manifest IDs. They have separate Workspace IDs, homes, tool-owned native auth,
containers, networks, principals, applied state, failures, and learned rules.
They deliberately mount the same live host source. A read-only source bind is
not a clone, overlay, lock, or integrity snapshot.

## Runtime image and container

A Runtime revision supplies the OS, tools, entrypoint, and runtime API. The
container realizes one applied entry at a point in time; neither defines
Workspace identity. Missing or drifted resources can be reconciled on the next
explicit entry while preserving identity and home.

Changing a Manifest Runtime binding creates a new desired revision. Bound
Workspaces show it as Next and retain Current until a successful entry. Runtime
build history is subordinate immutable state; WP03 owns delete/prune/restore.

## Cluster

The standard installation-local cluster contains Gateway and OPA, control and
egress networks, aggregate policy projection, principal registry, and CA
lifecycle. Shared services never erase Workspace authority: Gateway derives
the Workspace/Manifest principal from trusted registration, and OPA selects
policy by stable identity.

## Guarantees and limits

**Guaranteed:** stable Manifest/Workspace identity; explicit-only
reconciliation; last-success preservation; one Workspace per exact
root/Manifest pair; default selection separate from authority; runtime `CMD`
cannot replace Tobari's lifetime contract.

**Not guaranteed:** filesystem isolation for overlapping roots; automatic
inference after moving a project; trust in arbitrary custom images; automatic
pulls of configured local/custom images.

## Summary

The Workspace Manifest is the desired class-like definition. The Workspace is
the durable applied instance. The cluster is shared enforcement, and the
container is replaceable observed state.
