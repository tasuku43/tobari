---
title: Authenticate your tools
description: Run the coding agent's native login inside its Workspace while keeping login separate from outbound network permission.
---

The agent binary can exist without account credentials. On the release
surface, the agent CLI owns its login state inside the Workspace.

## Run native login

Run the tool directly through the ordinary entry path and follow its official
flow:

```sh
cd /path/to/your/project
tobari -- claude
# or
tobari -- codex login
# or
tobari -- gh auth login
```

You can also enter Bash first and run any installed native client there:

```sh
tobari

# Inside the Workspace
claude
# or
codex login
# or
gh auth login
# or
aws sso login --profile your-profile
```

Fresh first use still shows the one Start Workspace / Customize / Cancel review
before either form enters. A fresh shell may print one non-blocking reminder
that credentials stay in this Workspace; direct commands rely on the client's
native prompt. Tobari has no host login/setup stage and does not inspect
credential state.

The resulting state lives in this Workspace's persistent home. It survives
ordinary `exit` and work-container replacement, but is not copied from the host
or shared with another Workspace.

Attached native AWS SSO login relays its reviewed dynamic localhost callback to
this Workspace. If that callback mode is unavailable, use
`aws sso login --use-device-code --profile your-profile`.

## Login and policy remain separate

A successful provider login does not automatically allow an HTTP request.
Gateway hides credential values from OPA and audit, asks OPA about the exact
request effect, and forwards the original value only after allow.

The fixed agent-ready compatibility baseline already includes the pinned
Claude/Codex native-login and core endpoints when native readiness is enabled.
A new or optional endpoint can still be denied. From a separate trusted-host
terminal, run:

```sh
tobari review permissions
```

Review the exact destination, method, and path, approve only what you intend,
then retry in the existing Workspace.

## Credential lifetime

- `exit` leaves the Workspace and its native login state intact.
- Runtime rebuild or container recovery reuses the same Workspace home.
- `tobari workspace delete --id <workspace-ref> --confirm=delete` removes that exact
  Workspace home and its tool-owned credentials.
- Host homes, Keychain, SSH agents, and host credential variables are never
  inherited.
