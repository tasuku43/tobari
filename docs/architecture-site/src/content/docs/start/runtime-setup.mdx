---
title: Prepare a custom runtime
description: Add the coding agent and project tools you actually use to Tobari's minimal base runtime, then verify them inside a Workspace.
---

Quickstart deliberately used only `curl`. The standard base runtime is enough to experience Tobari's network boundary, but it is not a development environment.

For the first setup, keep Tobari's defaults and learn only this path:

1. create a reusable Runtime source tree;
2. add the coding agent and project tools;
3. build and validate the image; and
4. select its ready revision for a Workspace Template; and
5. enter a real project and verify the agent.

You do not need to learn configuration switching yet.

## 1. Create a Runtime source tree

Run this on the trusted host:

```sh
tobari runtime create --name coding
```

Tobari creates an owner-only `source/` directory and reports its path. It
contains a starter Dockerfile and may also contain scripts, manifests, and
configuration copied by that Dockerfile. Creation does not build an image or
change any Workspace Template.

## 2. Add the agent and project tools

Open the Dockerfile path printed by Tobari. Keep the generated base, entrypoint, and final `USER tobari`. Add installation commands between the generated `USER root` and `USER tobari` lines.

A minimal shape looks like this:

```dockerfile
# Keep the generated FROM line.

USER root

RUN apt-get update \
    && apt-get install -y --no-install-recommends \
       nodejs npm ripgrep \
    && rm -rf /var/lib/apt/lists/*

# Install your coding agent using its official method.
# RUN ...

USER tobari
```

Install only what the selected agent and project need. Pin versions where practical. Do not put access tokens, cloud credentials, host credential files, or private package-manager configuration into the image.

## 3. Build and validate the runtime

```sh
tobari runtime build --id RUNTIME_REF
```

Tobari snapshots the complete source tree, builds the snapshot, verifies the
runtime interface, and appends an immutable successful revision. A failed or
unchanged build changes no Workspace Template.

`runtime build` runs a Docker build on the host. Downloads performed by the Dockerfile do not pass through Workspace policy review, so review the base image and every download source used during the build.

## 4. Select the revision for a Workspace Template

```sh
tobari runtime history --name coding
tobari template plan --id TEMPLATE_REF
tobari template apply --plan TEMPLATE_CHANGE_PLAN_REF
```

Selection is explicit and the same revision can be reused by several Workspace Templates.
Building a later revision does not roll any Workspace Template forward.

## 5. Enter a real project and verify the agent

The Quickstart cleanup may have stopped the shared cluster, so make sure it is running before entering the project:

```sh
tobari cluster up
cd /path/to/your/project
tobari

# Inside the Workspace
command -v <agent-command>
<agent-command> --version
```

Replace the placeholder with the executable you installed. The agent and required project tools should now be available inside the Workspace.

If the project already had a Workspace using the previous runtime, entry may replace only its work container. Project files, the persistent Workspace home, and learned policy remain.

Installing the executable does **not** authenticate it and does **not** grant outbound network permission.

## Next: authenticate the tools you installed

Continue to [Authenticate your tools](../authentication-setup/). Configure only the accounts and external services your actual workflow needs.

## Later: separate configurations when you need them

One default setup is enough to learn and use Tobari initially. Later, you may want different runtimes, authentication sets, or policy-data boundaries for different jobs. Tobari groups those settings into named **Workspace Templates**.

Learn [Workspace Templates and separate configurations](../../guides/workspace-templates-and-contexts/) when that need appears. Workspace Template is not prerequisite knowledge for this first runtime build.
