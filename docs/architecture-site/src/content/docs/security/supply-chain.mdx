Tobari starts Gateway, OPA, and Auth Broker from reviewed immutable image
digests. Canonical source is checked against the embedded runtime snapshots used
by the CLI, while runtime metadata, licenses, and repository gates reject drift
before publication or release.

The default Workspace runtime selector is a different contract: it is currently
a moving tag, not an immutable service identity. Read
[Implementation stack](../../how-it-works/implementation-stack/) first for the
role of each image and embedded asset.

## Why source and snapshot both exist

The Go CLI must materialize a runtime directory without downloading executable policy or Python source at startup. Canonical editable Gateway code lives under `gateway/`; Auth Broker under `authbroker/`; runtime source under `runtimes/base/`. Byte/content-checked copies live under `internal/infra/runtimeassets/assets/` for embedding. The Auth Broker snapshot includes the private AWS companion protocol and fixed Datadog refresh logic, but its image contract rejects GitHub CLI, AWS CLI, `pup`, or another provider executable.

The copies are not a second implementation. `check-gateway-source.sh`, `check-authbroker-source.sh`, and `check-runtime-base.sh` reject drift. Synchronization is an explicit maintainer operation.

## Immutable and moving identities

`versions.env` pins OPA, mitmproxy build base, Gateway, Auth Broker, and Debian build base by `@sha256:` digest. Gateway and Auth Broker do not invent public SemVer values; their digest is the exact runtime identity. Friendly OPA/mitmproxy version strings are repository declarations paired with those digests.

The official default runtime selector is currently `ghcr.io/tasuku43/tobari/runtime:latest`. It is intentionally a moving selector and must not be described as an immutable digest. Context reconciliation resolves and records the image identity it actually uses; runtime API labels and metadata gate compatibility.

Canonical source and a pinned runtime artifact are two separate facts. A source
change does not alter a running or newly reconciled standard cluster until the
corresponding multi-architecture Gateway/Auth Broker manifest is published,
reviewed, and its immutable digest is updated in `versions.env`. The generated
[Component versions](/reference/component-versions/) table is the authority for
the artifacts this source snapshot actually selects.

At this snapshot, canonical Gateway/Auth Broker source is the complete paired
V1 authority. It remains a contributor snapshot rather than a publishable
standard-cluster artifact until reviewed immutable V1 indexes replace the
explicit unpublished marker. A successful source test does not silently
publish runtime bytes.

## Build and release controls

- OCI images are built in reviewed workflows and published to GHCR.
- External workflow actions are pinned to full commit SHAs.
- Release packaging injects CLI version and commit; ordinary builds remain `dev`.
- Base/derived runtime metadata records architecture, parent, API, lifetime command, tool source, checksum/signature, and licensing expectations.
- Auth Broker image checks prove the absence of provider CLIs and public TCP
  listeners; companion tests prove the host side exposes no listener or socket
  mount and accepts only its compiled AWS operation.
- Public and release guards check repository boundaries, secrets, licenses, package inputs, and immutable service references. Tobari does not claim a separate code-signing, SBOM-attestation, or externally verifiable provenance system here.

## Startup failure behavior

Missing, mutable where immutable is required, incompatible, or unverifiable images stop reconciliation. Missing embedded assets or source drift fail repository gates. Invalid policy/provider projections and locked/unsafe broker state stop dependent services from becoming ready. Failure does not switch to a different unreviewed image or download scripts dynamically.

  <h2>Guaranteed</h2>
  <div class="prose-block">
    Reviewed service identities are digest-pinned and source/snapshot equality
    is mechanically checked. The static documentation site itself uses a
    lockfile and no runtime CDN.

<aside class="limitation">
  <h2>Not guaranteed</h2>
  <div class="prose-block">
    A digest identifies bytes; it does not prove those bytes have no
    vulnerability. The default runtime tag is moving. The trusted registries,
    CI, host, and reviewed dependency process remain part of the supply-chain
    assumption.
  </div>
</aside>

## You should now be able to explain…

…why “pinned image” and “reviewed source snapshot” are related but different controls.

<div class="question-list">
  <details>
    <summary>Is `runtime:latest` immutable?</summary>
    <div class="prose-block">
      No. It is the current moving official selector. Service component digests
      and resolved runtime identities must be described separately.
    </div>
  </details>
  <details>
    <summary>Why embed Python/Rego source if canonical copies exist?</summary>
    <div class="prose-block">
      The CLI needs deterministic offline materialization. Equality checks keep
      the embedded copies from becoming independent implementations.
    </div>
  </details>
  <details>
    <summary>Does a digest prove an image is safe?</summary>
    <div class="prose-block">
      No. It provides exact identity. Review, tests, vulnerability checks,
      provenance, and trusted infrastructure are additional controls.
    </div>
  </details>
</div>
