This page is a developer index for tracing Tobari's public security behavior into the repository. It maps important behavior to the relevant design documents, implementation, and tests.

Use it to inspect topology, principal, policy, TLS, credential, lifecycle, and
supply-chain implementation at the commit fixed by this documentation. Read
[Supply chain](../supply-chain/) and the relevant How it works page before
interpreting an individual evidence row.

## How to interpret gaps

A unit test can prove a parser or state invariant without proving the real Docker topology. An integration test can prove an observed topology without proving every invalid document is rejected. Architecture plus configuration can explain the two-TLS design even though the current suite does not packet-capture both handshakes. This map therefore names different evidence types instead of pretending one test proves the entire claim.

<aside class="limitation">
  <h2>Evidence limitation</h2>
  <div class="prose-block">

    across cluster purge—is visible in deletion ownership and implementation,
    but does not have a dedicated single assertion for every retained file. The

    than overstating it.
