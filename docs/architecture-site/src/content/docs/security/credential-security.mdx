---
title: Credential security
description: Security guarantees and limits of standard native Workspace authentication.
---

## What standard protects

- Host credential files, Keychain, SSH agents, and credential environment are
  not mounted or copied into a Workspace.
- Each Workspace has an independent persistent home.
- Authentication and cookies are absent from OPA input, audit, denial output,
  and logs.
- An allowed request receives its original authentication only after policy;
  a denied request performs no upstream connection.
- The standard Gateway image and Compose topology contain no Broker provider
  binding path.

## What standard does not protect

All processes in one Workspace can read its native tool credential. Tobari
does not identify the authenticating process, prevent use of an already allowed
capability, revoke provider sessions remotely, or interpret provider-owned
credential files and account metadata.

## Lifecycle

Native credential state survives `exit`, runtime rebuild, and container
recovery because it belongs to the Workspace home. `tobari delete` removes that
home. A separate Workspace requires a separate native login.

## Experimental boundary

Broker handles, encrypted vaults, root keys, refresh/signing plans, and
provider acquisition exist only in the compile-time experimental development
profile. They receive synthetic security coverage but are not standard or
release capabilities.
