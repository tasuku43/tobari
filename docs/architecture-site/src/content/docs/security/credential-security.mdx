---
title: Credential security
description: Security guarantees and limits of standard native Workspace authentication.
---

## What the release surface protects

- Host credential files, Keychain, SSH agents, and credential environment are
  not mounted or copied into a Workspace.
- Each Context has an independent persistent Home mounted into every Workspace
  it owns.
- Authentication and cookies are absent from OPA input, audit, denial output,
  and logs.
- An allowed request receives its original authentication only after policy;
  a denied request performs no upstream connection.
- The release Gateway image and Compose topology expose no Tobari-owned
  authentication command or credential service.

## What the release surface does not protect

All processes in every Workspace owned by one Context can read the native tool
credentials in their shared Context Home. Tobari does not identify the
authenticating process, isolate mutually hostile sibling Workspaces, prevent use
of an already allowed capability, revoke provider sessions remotely, or
interpret provider-owned credential files and account metadata.

## Lifecycle

Native credential state survives `exit`, runtime rebuild, container recovery,
and Workspace replacement because it belongs to the Context Home. Exact
`context delete` removes that Home after no Workspace or attachment remains. A
separate Context requires a separate native login.
