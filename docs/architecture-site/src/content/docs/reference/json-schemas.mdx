Tobari uses versioned JSON for several different surfaces. A public CLI report,
a persisted Context manifest, a Gateway policy request, and an Auth Broker frame
are separate contracts even when they describe related state. A schema number
has meaning only together with the name of its surface.

The owning Catalog entry, parser, or protocol implementation is authoritative.
This page summarizes those contracts at the product snapshot shown in the page
footer.

Exact fields, optionality, output formats, and command coverage are generated in
the [CLI reference](/reference/cli/). Consumers must select behavior by the
exact envelope and `schema_version`; a field present in one envelope is not
implicitly part of another.

## Context storage and presentation are different contracts

```text
Host configuration
  contexts/<name>/context.json
  Context manifest schema 5

CLI presentation
  {"schema_version": 8, "context": ...}
  public Context report schema 8
```

The public report adds runtime, cluster, shell, Git, and secret-free
authentication interpretation. It is not a byte-for-byte rendering of
`context.json`.

## Important persisted host contracts

| State                                  | Current contract          |
| -------------------------------------- | ------------------------- |
| Context manifest                       | Schema 5                  |
| Root index and Workspace instance      | Schema 2                  |
| Shared cluster state                   | Schema 3                  |
| Project principal registry             | Schema 2                  |
| Guided policy data                     | `tobari.schema_version` 2 |
| Aggregate policy projection marker     | Schema 1                  |
| Owner provider manifest                | Schema 1                  |
| Reviewed built-in provider manifest    | Schema 1 or 2             |
| Normalized provider projection         | Schema 2                  |
| Encrypted Context vault                | Envelope 1; payload 2     |
| Workspace authentication file registry | Schema 1                  |
| Base runtime metadata                  | Schema 1                  |

The Context vault can contain typed static credentials, opaque AWS state,
Datadog OAuth state, OpenAI Codex OAuth state, Anthropic static-token state,
revisions, durable ambiguity barriers, and raw handles. None of those internal
values becomes public CLI output merely because the public `auth` envelope
summarizes its state.

## Gateway, OPA, audit, and Broker contracts

| Boundary                             | Current contract | Important rule                                                                                                                   |
| ------------------------------------ | ---------------: | -------------------------------------------------------------------------------------------------------------------------------- |
| Gateway credential configuration     |         Schema 2 | Contains managed projection metadata, not policy authority.                                                                      |
| Gateway → OPA decision input         |         Schema 5 | Host-derived principal and normalized HTTP attributes; no ordinary body or client secret header.                                 |
| Guided/Advanced source policy        |  Source schema 4 | Legacy source schema 3 is accepted only for migration; aggregate output is runtime schema 5.                                     |
| Gateway audit line                   |         Schema 2 | Bounded, secret-free decision evidence.                                                                                          |
| Learnable-denial navigation response |         Schema 1 | Fixed host-review guidance; no candidate ID, query, body, or secret.                                                             |
| Broker control protocol              |         Schema 1 | Bounded newline-delimited JSON on the host control socket.                                                                       |
| Broker runtime protocol              |         Schema 1 | Non-secret introspection followed, after allow, by a declared static resolve, Datadog/OpenAI token action, or AWS signing result. |
| Private host companion frames        |         Schema 1 | Authenticated, direction-bound, strictly sequenced frames for the compiled AWS operation.                                        |
| Workspace Broker handle              | Handle version 1 | Opaque `tobari-h1_…` bytes; never decode them into authority.                                                                    |

OPA returns a decision. Gateway owns the external connection and fails closed
when the decision is unavailable or malformed.

## Compatibility rules

- Treat an unknown version as unsupported; do not coerce it to the newest shape.
- Preserve the difference between absent and explicit empty, zero, or false
  when the named contract requires it.
- Treat opaque references and handles as exact bytes. Do not normalize,
  truncate, decode, or reconstruct them.
- Do not infer identity from display labels, array order, indentation, or
  proximity.
- Use the public CLI rather than reading internal state as an integration API.
- When a mutation result is uncertain, inspect the authoritative status or
  report surface before retrying.

## Failure behavior

Malformed, oversized, unsafe, or unsupported persisted and protocol documents
are rejected by their owning reader. Compatibility is deliberately
surface-specific: support for an older Context manifest does not imply support
for an older Broker frame or a future public CLI envelope.

## Summary

A version is scoped to one named surface. Public CLI schemas, persisted state,
policy input, audit records, and Broker protocols must be interpreted and
upgraded independently.
