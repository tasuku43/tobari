This reference lists Tobari's versioned JSON surfaces and their exact boundaries. A
public CLI report, persisted manifest, Gateway policy input, and
audit line are separate contracts even when they
describe related objects.

Each schema belongs to one specific surface. Schema numbers are local to that
surface: the current public CLI includes V1, V2, and V3 envelopes, while
structured errors are V2. The owning parser, Catalog entry, or protocol
implementation is the source of truth for each surface below.

## “Schema” does not always mean JSON Schema

Tobari uses explicit `schema_version` fields and strict readers for many JSON
contracts. The repository does not currently publish a formal JSON Schema
document for every surface. The Go parsers and validators enforce the public
Workspace Template, Runtime, Workspace, policy, and report contracts, with canonical
synthetic fixtures recorded in the harness ledger.

For public CLI output, the Catalog declares the JSON envelope and schema
version. Contract tests execute the renderer and compare the produced
`schema_version` to the Catalog. For persisted or internal documents, the
owning domain or infrastructure reader defines exact validation.

### Final authority contract boundary

The persisted owner envelope and public task projections remain distinct:

```text
Persisted final authority
  workspace-authority/authority.json
  complete atomic collection schema 1

CLI presentation
  {"schema_version": 1, "template": ...}
  task-owned final Template report schema 1
```

Public Template, Context, Workspace, and entry results are task-owned
projections, not the complete bytes stored in the atomic final-authority
envelope.

## Persisted host contracts

| State                                       | Current contract  |
| ------------------------------------------- | ----------------- |
| Atomic final-authority collection           | Schema 1          |
| Managed Runtime library and lifecycle state | Schema 1          |
| Workspace-owned agent state                 | Tool-owned format |
| Base Runtime metadata                       | Schema 1          |

Readers reject malformed, oversized, unsafe, or unsupported state according to
the owning contract. Strictness is surface-specific: do not assume that every
JSON reader accepts or rejects an unknown field in the same way. Final
authority and critical Runtime state use explicit fail-closed validation.

This pre-release clean break has no predecessor compatibility reader and no
implicit or public migration. A bounded presence-only guard classifies legacy
authority without decoding or adopting it, then fails read-only with
reset-and-recreate guidance.

## Gateway, OPA, audit, and authentication contracts

| Boundary                                     | Current contract | Important content rule                                                                        |
| -------------------------------------------- | ---------------: | --------------------------------------------------------------------------------------------- |
| Gateway request metadata                     |         Schema 1 | Final Context/Workspace projection; contains paths/metadata, not policy authority.            |
| Gateway → OPA decision input                 |         Schema 1 | Host-derived principal plus normalized HTTP attributes. No body and no client secret headers. |
| Template-policy and Policy Memory input      |         Schema 1 | Activation validates the exact final Context-owned source before publication.                 |
| Gateway audit line                           |         Schema 1 | Secret-free normalized decision evidence.                                                     |
| Gateway learnable-denial navigation response |         Schema 1 | Fixed host review guidance; no candidate ID, query, body, or secret.                          |

OPA output is a decision consumed by Gateway. OPA does not open an upstream
connection. A wrong or unavailable policy response fails closed before
upstream connection.

Runtime control uses bounded newline-delimited JSON frames. Credential-bearing
values remain agent-owned request data and are not JSON metadata.

## Exact version rules for consumers

- Select behavior by the exact envelope and `schema_version`.
- Treat unknown versions as unsupported. Do not silently coerce them to the
  newest known shape.
- Preserve absent versus explicit empty, zero, or false when the contract says
  the distinction matters.
- Treat opaque references as exact bytes. Do not decode, normalize,
  truncate, or reconstruct them.
- Do not infer identity or relationships from labels, array order, proximity,
  or human indentation.
- Do not read internal state files as a substitute for a supported public CLI
  result.

## Failure and limits

A schema mismatch is a contract failure, not permission to
guess. Tobari preserves known-good policy or runtime selection when candidate
validation fails. Invalid runtime frames fail closed. Public errors omit arbitrary wrapped upstream prose because it may
contain URLs, response bodies, or credentials.

This page records current contracts; it is not a promise that every internal
format is a public extension point. Only the Catalog and explicitly documented
external contracts are supported public boundaries.

## Summary

Schema identities remain local to a boundary. Exact readers and tests define
each contract; a shared number does not make distinct documents
interchangeable.

## Check your understanding

You should now be able to explain why a schema number is incomplete without
its surface.

<details>
  <summary>Can user policy select another evaluator schema?</summary>

No. User policy is canonical typed data. Tobari selects and verifies its fixed
evaluator, then tests the complete candidate before publication.

</details>

<details>
  <summary>May a client decode an opaque reference to recover an ID?</summary>

No. It must preserve and return the exact validated value to the command that
consumes its reference kind.

</details>
