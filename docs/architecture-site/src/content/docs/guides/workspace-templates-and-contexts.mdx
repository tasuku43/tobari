---
title: Workspace Templates and Contexts
description: Reuse one reviewed setup, bind it to a Project with a Context, and enter its replaceable Workspace.
---

A **Workspace Template** is reusable installation setup. A **Context** binds one
canonical Project root to one Template and owns that Project's remembered
policy decisions. A **Workspace** is the replaceable applied instance and
persistent home for one Context.

## Discover Templates

```sh
tobari template list --format json
tobari template show --name review --format json
```

Names are read-only discovery text. Actions consume the opaque references
returned by discovery.

## Create or copy

Create a reviewed setup with immutable read-only source access and one bounded
exact GraphQL endpoint:

```sh
tobari template create --name review --source-access read-only --graphql-endpoint https://graphql.example.dev:8443/graphql
```

Use `--source-access read-write` for a writable Project root, or omit it to
keep the default. The endpoint must be an exact HTTPS URL with an explicit
port and path; it is stored in the Template's bounded POST policy. `template
list` and `template show` expose the resulting opaque references for the next
Context step.

Copy one exact retained immutable revision:

```sh
tobari template show --name default --format json
tobari template copy --from TEMPLATE_REVISION_REF --name review
```

Copy creates a fresh unpublished Template identity and source pair with null
`base_revision`. A later fresh Plan and Apply publish generation 1. Copy carries
no Context, Policy Memory, Workspace, home, credentials, attachment, applied
state, default selection, or lineage.

## Select the installation default

```sh
tobari template list --format json
tobari template default set --id TEMPLATE_REF
```

Default selection affects only bare root entry and bare `status`. It never
retargets an existing Context or Workspace.

## Bind this Project and enter

From the Project root:

```sh
tobari context create --template TEMPLATE_REF
tobari context enter --id CONTEXT_REF
```

For ordinary default work, bare `tobari` creates or reuses the default
Template/Context pair and enters its Workspace. For nondefault work, obtain the
Context reference from `context list` or `context show` and pass it unchanged
to `context enter`.

```sh
tobari context list --format json
tobari context show --id CONTEXT_REF --format json
tobari context enter --id CONTEXT_REF -- codex exec ...
```

## Configure one exact Template

```sh
tobari template plan --id TEMPLATE_REF
tobari template apply --plan TEMPLATE_CHANGE_PLAN_REF
```

Apply publishes a complete immutable Template revision. Runtime and
session defaults apply only at their documented later entry/session boundary;
bootstrap applies only to a newly created Workspace home.

## Observe and delete

Bare status is the zero-mutation CWD home:

```sh
tobari status --format json
```

Nondefault resources use exact references:

```sh
tobari workspace status --id WORKSPACE_REF --format json
tobari workspace delete --id WORKSPACE_REF --confirm=delete
tobari context delete --id CONTEXT_REF --confirm=delete
tobari template delete --id TEMPLATE_REF --confirm=delete
```

Workspace deletion removes its home and native credentials but preserves
Context Policy Memory. Context deletion requires no Workspace, attachment, or
research credential. Template deletion requires that it is neither the default
nor referenced by a Context.
