Tobari は Gateway、OPA、Auth Broker を、レビュー済みの変更されないイメージダイジェスト
から起動します。CLI が使う埋め込みランタイムのスナップショットと正本のソースが一致する
ことを検査し、ランタイムのメタデータ、ライセンス、リポジトリの検証ゲートによって、
公開またはリリース前の差分を拒否します。

Workspace のデフォルトランタイム選択子は別の契約で、現在は変更されないサービス
識別情報ではなく、更新されるタグです。各イメージと埋め込み成果物の役割は、
先に[実装技術](../../how-it-works/implementation-stack/)で確認できます。

## 正本とスナップショットの両方がある理由

Go CLI は起動時に実行可能なポリシーや Python ソースをダウンロードせず、ランタイム
ディレクトリを展開できる必要があります。編集する正本は、Gateway が `gateway/`、
Auth Broker が `authbroker/`、ランタイムが `runtimes/base/` にあります。
埋め込み用にバイト列と内容の一致を検査する複製は、
`internal/infra/runtimeassets/assets/` にあります。Auth Broker のスナップショットには、
非公開の AWS コンパニオンプロトコルと、接続先を固定した Datadog 更新処理が含まれます。
ただしイメージ契約では、GitHub CLI、AWS CLI、`pup`、その他のプロバイダー実行
ファイルがイメージに入ることを拒否します。

埋め込みの複製は二つ目の実装ではありません。`check-gateway-source.sh`、
`check-authbroker-source.sh`、`check-runtime-base.sh` が正本との差分を拒否します。
同期は保守担当者が明示的に行う操作です。

## 変更されない識別情報と更新される識別情報

`versions.env` は OPA、mitmproxy のビルド元、Gateway、Auth Broker、Debian の
ビルド元を `@sha256:` ダイジェストで固定します。Gateway と Auth Broker に架空の
公開 SemVer は付けません。そのダイジェストがランタイムの完全一致の識別情報です。
読みやすい OPA と mitmproxy のバージョン文字列は、ダイジェストと組み合わせてリポジトリが
宣言する情報です。

公式のデフォルトランタイム選択子は、現在
`ghcr.io/tasuku43/tobari/runtime:latest` です。意図的に更新される選択子であり、
変更されないダイジェストと説明してはいけません。Context の状態調整では、実際に使う
イメージの識別情報を解決して記録します。互換性はランタイム API ラベルとメタデータで
検査します。

正本のソースと、ダイジェストで固定したランタイム成果物は別の事実です。ソースが
変わっても、対応する複数アーキテクチャの Gateway と Auth Broker のマニフェストを
公開してレビューし、`versions.env` の変更されないダイジェストを更新するまでは、実行中または
新たに状態を調整する標準クラスターのバイト列は変わりません。このソースのスナップショット
が実際に選ぶ成果物は、生成された[コンポーネントバージョン](../../reference/component-versions/)
の表を正本として確認できます。

このスナップショットでは、Gateway と Auth Broker の正本ソース全体が一組の V1 権限です。
レビュー済みの不変な V1 索引が明示的な unpublished マーカーを置き換えるまでは、公開可能な
標準クラスター成果物ではありません。ソースのテストが成功しただけで、ランタイム成果物が
暗黙に公開されることはありません。

## ビルドとリリースの制御

- OCI イメージはレビュー済みのワークフローでビルドし、GHCR へ公開する
- 外部ワークフローのアクションは完全なコミット SHA で固定する
- リリースパッケージには CLI のバージョンとコミットを埋め込み、通常のビルドは `dev` のままにする
- 基盤ランタイムと派生ランタイムのメタデータには、アーキテクチャ、親、API、寿命を保つ
  コマンド、ツールのソース、チェックサムまたは署名、ライセンスの要件を記録する
- Auth Broker イメージの検査では、プロバイダー CLI と公開 TCP リスナーが存在しない
  ことを確認する。コンパニオンのテストでは、ホスト側にリスナーやソケットのマウントが
  なく、コンパイル済みの AWS 操作だけを受け入れることを確認する
- 公開・リリース用の検査は、リポジトリ境界、秘密情報、ライセンス、パッケージ入力、
  変更されないサービス参照を確認する。独立したコード署名、SBOM の証明、外部から
  検証できる来歴管理の仕組みまでを保証するものではない

## 起動に失敗したときの動作

必要な識別情報が存在しない、変更されないはずの参照が可変である、互換性がない、
または検証できない場合は、状態調整を停止します。埋め込み成果物がない、または正本の
ソースと一致しない場合は、リポジトリの検証ゲートが失敗します。ポリシーやプロバイダーの
投影結果が不正、Broker がロック中または安全でない状態の場合、依存するサービスは
準備完了になりません。障害時に、レビューしていない別のイメージへ切り替えたり、
スクリプトを動的にダウンロードしたりすることはありません。

<aside class="guarantee">
  <h2>保証すること</h2>
  <div class="prose-block">
    レビュー済みのサービス識別情報はダイジェストで固定され、ソースとスナップショットの
    一致は機械的に確認されます。静的ドキュメントサイト自体も lockfile を使い、
    実行時に CDN を読み込みません。
  </div>
</aside>

<aside class="limitation">
  <h2>保証しないこと</h2>
  <div class="prose-block">
    ダイジェストが示すのはバイト列の識別情報であり、その内容に脆弱性がないことでは
    ありません。デフォルトランタイムのタグは更新されます。信頼するレジストリ、
    CI、ホスト、レビュー済みの依存関係管理手順は、サプライチェーンの前提です。
  </div>
</aside>

## ここまでで説明できること

「固定されたイメージ」と「レビュー済みのソースのスナップショット」は関係しますが、別々の
制御です。

<div class="question-list">
  <details>
    <summary>
      <code>runtime:latest</code> は不変ですか？
    </summary>
    <div class="prose-block">
      いいえ。現在の公式選択子は更新されます。サービスコンポーネントの
      ダイジェストと、実際に解決したランタイムの識別情報は別々に扱います。
    </div>
  </details>
  <details>
    <summary>
      正本があるのに Python/Rego のソースを埋め込むのはなぜですか？
    </summary>
    <div class="prose-block">
      CLI
      が、ネットワークを使わず決定的にファイルを展開できる必要があるためです。
      一致検査によって、埋め込みの複製が独立した実装になるのを防ぎます。
    </div>
  </details>
  <details>
    <summary>ダイジェストはイメージが安全だと証明しますか？</summary>
    <div class="prose-block">
      いいえ。ダイジェストは完全一致の識別情報を与えるだけです。レビュー、テスト、
      脆弱性検査、来歴の確認、信頼する基盤は、それぞれ別の制御です。
    </div>
  </details>
</div>
