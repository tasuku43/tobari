---
title: 監査とプライバシー
description: ポリシー学習と診断のために記録する情報、除外する情報、秘密情報を含まなくても内容が空ではない理由を説明します。
---

Tobari が保持するのは、HTTP 通信を説明し、レビューするために必要な範囲の
メタデータです。リクエスト本文、Auth Broker のハンドル、解決後の秘密情報、
設定済みの認証ヘッダーは除外します。ただし、URL のパス、クエリの値、分類されて
いないヘッダーまで、機微情報ではないと判断するわけではありません。

ここで扱うのはポリシーと診断のための記録です。汎用的な情報漏えい防止機能では
ありません。この記録が作られるリクエストと認証情報の境界は、
先に [リクエストの流れ](../../how-it-works/request-journey/) と
[認証情報の安全性](../credential-security/) で確認できます。

## 許可判断の入力に含まれるもの

Gateway は、信頼できるプリンシパルと正規化した HTTP 情報からスキーマ 1 の入力を
作ります。スキーム、正規化したホスト、確定したポート、メソッド、未加工と復号後の
パス、複数の値を持つクエリー、認証情報を伏せたヘッダー、秘密情報を含まない認可
メタデータが対象です。リクエスト本文は含みません。

設定または認識済みの秘密ヘッダーと Auth Broker のハンドルは、削除するか値を
伏せます。ただし、秘密情報らしい文字列をすべて発見できるわけではありません。
URL のパス、クエリ、分類されていないヘッダーに機密データを入れると、その値が
許可判断用のメタデータや診断情報に含まれる可能性があります。

## 保持する拒否の根拠に含まれるもの

学習可能な拒否は、上限を設けたスキーマ 1 の JSON 監査レコードとして記録します。
Workspace Manifest とプロジェクトの識別情報、ホスト、ポート、メソッド、パス、判断と理由、リクエスト
ID、時刻、処理時間、秘密情報を含まない分類メタデータが対象です。ポリシーの
検出処理は、上限付きで Docker ログを読み、完全一致規則の各項目で候補をまとめます。

本文の違いによって候補が分かれることはありません。クエリと安全なヘッダーは OPA
の入力に現れる場合がありますが、現在の学習済み完全一致規則を識別する項目には
なりません。レビュー用の参照値は SHA-256 から導出した不透明な参照です。
利用者は表示順や復号したプロバイダー表記ではなく、受け取った参照値をそのまま
操作へ渡します。

## 公開出力に含めてはいけないもの

- 実物の認証情報、ルート鍵、復号した保管庫の内容
- Auth Broker のハンドル値
- リクエスト本文とレスポンス本文
- 認証情報を含む外部接続先側の原因
- 非公開の組織名やアカウントを含むテストデータ、偶発的に混入したビルド環境のパス。
  ただし、信頼できる基準プロジェクトルートは意図した診断情報であり、ホスト側の
  出力に現れる場合があります
- 端末、TSV、JSON、Unicode の行構造を壊す未加工の制御文字

表示用の変換では、制御文字、書式文字、バックスラッシュ、Unicode の行区切りを
区別します。表示可能な文字列が命令文のように見えるという理由だけで除去することは
ありません。外部から届く文字列は、表示後も信頼しないデータです。

## 保持期間とプライバシーの境界

Gateway のログ量は Docker のログ設定で制限します。検出処理が
参照するのも一定範囲の期間だけで、完全な履歴台帳ではありません。候補の根拠が
見つからない、または保持期間を過ぎた場合、利用者はその候補を安全に操作できません。
規則の集約は自動実行されません。

このサイトはアクセス解析、追跡機能、実行時の API 呼び出し、外部フォント、Cookie を
使いません。ブラウザーに保存するのはローカルのテーマ設定だけです。

## 失敗時の動作

監査記録の保持に失敗しても、許可判断は変わりません。拒否されたリクエストは拒否の
ままです。候補が古い、または保持範囲から外れた場合、ホスト側の変更操作は拒否され、
再検出が必要になります。診断情報だけで再実行が許可されることはありません。

<aside class="guarantee">
  <h2>保証すること</h2>
  <div class="prose-block">
    対応するポリシー処理と Auth Broker の処理では、本文と認識済みの認証情報を
    OPA の入力と保持する監査記録から意図的に除外します。公開 CLI 出力では、悪意
    ある文字列を安全に表示する変換と、上限を定めたスキーマを適用します。
  </div>
</aside>

<aside class="limitation">
  <h2>保証しないこと</h2>
  <div class="prose-block">
    通常のパス、クエリ、分類されていないヘッダー自体が機微情報を含む場合があります。
    「秘密情報を含まない」とは、認証情報と本文に分類されるデータを除外するという
    意味です。あらゆる情報漏えいを検出する仕組みではありません。
  </div>
</aside>

## ここまでで説明できること

「本文を含まない」「認証用の秘密情報を含まない」「利用者の機微な文字列を含まない」
という三つの主張は、それぞれ意味が異なります。
