このページでは、Tobari の重要なセキュリティ上の主張を、governing contract、
enforcement source、test へ対応付けます。一つの test だけで主張全体を証明できない
場合は、より広い coverage があるように見せず、必要な configuration と
implementation evidence の組み合わせを明示します。

この documentation が固定する commit に対して、topology、principal、policy、
TLS、credential、lifecycle、supply-chain の claim を検証するための索引です。
各行を読む前に [Supply chain](../supply-chain/) と、関連する How it works page を
確認してください。

## 根拠が不足している箇所の読み方

unit test は parser または state invariant を証明できますが、real Docker topology までは証明できません。integration test は観測された topology を証明できますが、すべての invalid document が拒否されることまでは証明できません。current suite は二つの handshake を packet capture していませんが、architecture と configuration を組み合わせれば two-TLS design を説明できます。そのため、この map は一つの test が claim 全体を証明すると装うのではなく、異なる種類の evidence を明示しています。

<aside class="limitation">
  <h2>根拠の制限</h2>
  <div class="prose-block">
    cluster purge をまたぐ vault/root-key の survival など、一部の preservation
    behavior は deletion ownership と implementation
    から確認できますが、保持されるすべての file に dedicated single assertion
    があるわけではありません。この table は evidence
    を過大に述べず、implementation evidence と direct test coverage
    を区別します。
  </div>
</aside>
