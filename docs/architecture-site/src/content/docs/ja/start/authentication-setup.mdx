---
title: ツールを認証する
description: coding agent のネイティブログインを Workspace 内で実行し、ログインと外向きネットワーク権限を分離します。
---

agent binary が存在していても、account credential があるとは限りません。
release surface では agent CLI が Workspace に mount された Context Home 内のログイン状態を所有します。

## ネイティブログインを実行する

project に入り、通常の entry path からツールを直接実行して公式 flow に従います。

```sh
cd /path/to/your/project
tobari -- claude
# or
tobari -- codex login
# or
tobari -- gh auth login
```

Bash に入ってから、インストール済みの native client を実行することもできます。

```sh
tobari

# Inside the Workspace
claude
# or
codex login
# or
gh auth login
# or
aws sso login --profile your-profile
```

fresh first use では、どちらの形式でも入室前に Start Workspace / Customize /
Cancel の review が一度だけ表示されます。fresh shell では credential がこの
Workspace に残ることを一行だけ案内する場合があります。direct command は client
自身の prompt を使います。Tobari は host login/setup stage を持たず、credential
state を検査しません。

生成された状態はこの Workspace に mount された Context Home に保存されます。通常の `exit`、
work container の置換、Workspace の削除後も残りますが、host からコピーされず、別 Context とも
共有されません。

attached native AWS SSO login では、review 済みの動的 localhost callback がこの
Workspace へ relay されます。この callback 方式が利用できない場合は
`aws sso login --use-device-code --profile your-profile` を使います。

## ログインと policy は別

ログインが成功しても HTTP request は自動的に許可されません。Gateway は認証
情報を OPA と audit から隠し、正確な request effect を OPA に問い合わせ、allow
後だけ元の credential を upstream へ渡します。

固定の agent-ready compatibility baseline は native readiness が enabled の Workspace Template に
pinned Claude/Codex のネイティブログインと core endpoint を提供します。新しい optional endpoint は deny されることがあり
ます。別の trusted-host terminal で次を実行します。

```sh
tobari review permissions
```

正確な destination、method、path を確認し、意図したものだけを approve して、
既存 Workspace で再試行します。

## credential の lifetime

- `exit` 後も Workspace とネイティブログイン状態は残ります。
- runtime rebuild や container recovery は同じ Context Home を使います。
- `tobari workspace delete --id <workspace-ref> --confirm=delete` は Context Home と
  tool-owned credential を置換後の Workspace のために保持します。Workspace と
  attachment がない状態で `context delete` を行うと削除します。
- host home、Keychain、SSH agent、host credential variable は継承されません。
