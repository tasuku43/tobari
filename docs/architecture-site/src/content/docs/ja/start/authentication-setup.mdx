---
title: ツールを認証する
description: coding agent のネイティブログインを Workspace 内で実行し、ログインと外向きネットワーク権限を分離します。
---

agent binary が存在していても、account credential があるとは限りません。
standard profile では agent CLI が Workspace 内のログイン状態を所有します。

## ネイティブログインを実行する

project に入り、ツールの公式 flow に従います。

```sh
cd /path/to/your/project
tobari

# Inside the Workspace
claude
# or
codex login
# or
gh auth login
```

生成された状態はこの Workspace の永続 home に保存されます。通常の `exit` や
work container の置換後も残りますが、host からコピーされず、別 Workspace とも
共有されません。

## ログインと policy は別

ログインが成功しても HTTP request は自動的に許可されません。Gateway は認証
情報を OPA と audit から隠し、正確な request effect を OPA に問い合わせ、allow
後だけ元の credential を upstream へ渡します。

default の `builtin/agent-ready` には pinned Claude/Codex のネイティブログインと
core endpoint が含まれます。新しい optional endpoint は deny されることがあり
ます。別の trusted-host terminal で次を実行します。

```sh
tobari policy review
```

正確な destination、method、path を確認し、意図したものだけを approve して、
既存 Workspace で再試行します。

## credential の lifetime

- `exit` 後も Workspace とネイティブログイン状態は残ります。
- runtime rebuild や container recovery は同じ Workspace home を使います。
- `tobari delete` は Workspace home と tool-owned credential を削除します。
- host home、Keychain、SSH agent、host credential variable は継承されません。
