最初から Tobari のすべての概念を理解する必要はありません。まずは、新しく覚えることを最小限にしたまま、一連の作業を最後まで通せることを目標にします。

最初は初期設定をそのまま使います。通信の拒否とレビューを体験し、実作業用のランタイムを作り、必要なツールの認証を通します。内部構造、セキュリティ境界、復旧、設定の切り替えは、その後で学びます。

## 理解を積み上げる五つの段階

1. **境界を体験する:** 一つの通信を送り、拒否を確認し、ホスト側でレビューしてから再実行する。
2. **実作業できる状態にする:** コーディングエージェントと開発ツールを追加し、必要な認証を設定する。
3. **仕組みを理解する:** 一つの HTTP/HTTPS リクエストとポリシーレビューの処理順序を追う。
4. **境界を理解する:** 認証情報の経路、保証、障害時の動作、復旧を確認する。
5. **必要になったら設定を分ける:** 初期設定の流れに慣れてから、Workspace Template、別ランタイム、より厳格なポリシーへ進む。

## 推奨する 11 ステップ

### 1. Tobari が制御する範囲を知る

[概要](../overview/)を読みます。最初は、Workspace が触れられる範囲、信頼するホスト側に残る権限、HTTP/HTTPS 通信が Gateway を通ることだけを押さえれば十分です。

### 2. ポリシーの一連の動作を体験する

[クイックスタート](../quickstart/)を完了します。最小ベースランタイムの `curl` を使い、コーディングエージェントを選ぶ前に、拒否、ホスト側のレビュー、完全一致の許可、新しいリクエストとしての再実行を体験します。

### 3. 実際に使うランタイムを作る

[カスタムランタイムを用意する](../runtime-setup/)へ進みます。使いたいコーディングエージェントと開発ツールを追加し、`tobari runtime build` を実行します。その後、実際のプロジェクトから Workspace に入り、エージェントの実行ファイルを確認します。

ここでは Tobari の初期設定をそのまま使います。設定の切り替え方はまだ学びません。

### 4. インストールしたツールの認証を設定する

[ツールの認証を設定する](../authentication-setup/)へ進みます。永続的な Workspace home の中で agent CLI 自身のログインを完了します。Tobari はホスト側の認証サービスを追加しません。

ログインと外部通信の許可は別です。認証後の最初の API 通信が拒否された場合も、クイックスタートと同じようにレビューします。

ここまでで最初の一連の導入は完了です。初期設定のまま通常の作業を始められます。

### 5. 主要コンポーネントを理解する

[基本モデル](../../how-it-works/mental-model/)を読みます。実際の流れを一度経験した後で、Workspace、Workspace home の agent CLI ログイン、Gateway、OPA、外部の接続先がそれぞれ何を担当するか整理します。

### 6. 一つのリクエストを正確に追う

[リクエストの流れ](../../how-it-works/request-journey/)と [HTTPS と TLS](../../how-it-works/https-and-tls/)を読みます。Workspace からポリシー判断を経て、Gateway が別の外部接続を作るまでを番号順に追います。

### 7. ポリシーレビューを詳しく理解する

[ポリシー学習](../../how-it-works/policy-learning/)と[最初の拒否](../first-denial/)を読みます。完全一致ルール、不透明な参照値、ポリシー全体の検証、元のリクエストを自動再送しない理由を確認します。

### 8. 認証情報とセキュリティ上の保証を理解する

[認証情報](../../how-it-works/credentials/)、[認証の詳細](../../guides/authentication/)、[保証と制限](../../security/guarantees-and-limitations/)、[信頼境界](../../security/trust-boundaries/)を読みます。

ここでは「使える」状態から一段進み、「何を保証し、その保証がなぜ成立するのか」を説明できる状態を目指します。

### 9. 寿命と復旧を理解する

[Workspace のライフサイクル](../../how-it-works/workspace-lifecycle/)、[状態と復旧](../../how-it-works/state-and-recovery/)、[トラブルシューティング](../../guides/troubleshooting/)を読みます。シェル終了、作業コンテナの置き換え、Workspace の削除、サービス障害、クラスターの削除を区別します。

### 10. 設定を分ける必要が出たら Workspace Template を学ぶ

初期設定一つで足りるなら、このステップは後回しにできます。

用途ごとにランタイム、認証設定、ポリシーモードを分けたくなった段階で、[設定を分ける（Workspace Template）](../../guides/workspace-templates-and-contexts/)を読みます。その後、[Workspace、Workspace Template、クラスター](../../how-it-works/workspace-template-context-workspace-cluster/)、[ランタイムの詳細設定](../../guides/runtime-customization/)、[高度なポリシー](../../guides/advanced-policy/)へ進みます。

Workspace Template をここで初めて導入するのは意図的です。複数の設定を使い分ける必要が出たときに価値が分かる概念であり、最初の実行を成功させるための前提知識ではありません。

### 11. 理解度を確認する

[理解度チェック](../understanding-check/)に取り組みます。回答を開く前に、最初の一連の利用手順と Tobari のセキュリティ境界を自分の言葉で説明します。

## リファレンスを使うタイミング

リファレンスは、正確なコマンド契約、スキーマ、保存場所、バージョン、障害コードを調べるときに使います。どの処理を調べたいか分からない段階では、先に上の学習順を進めてください。

- [CLI](../../reference/cli/) はコマンドの正確な動作を確認するときに使います。
- [ランタイムイメージ契約](../../reference/runtime-image-contract/)は互換性条件を確認するときに使います。
- [設定と状態](../../reference/configuration-and-state/)は保存場所と寿命を確認するときに使います。
- 外部サービス固有の research 契約は public site に公開しません。Workspace 内では
  agent 自身の native authentication を使います。
- [障害と復旧](../../reference/faults-and-recovery/)は障害コードから安全な次の操作を調べるときに使います。

## まとめ

最初に学ぶ順番は、

**ポリシーの体験 → ランタイム → 認証 → 通常作業 → 内部の仕組み → セキュリティ → 復旧 → 必要なら設定の切り替え**

です。

この順番は意図的です。利用者が必要性を感じる前に、抽象概念を前提知識として要求しません。

**次へ:** [概要](../overview/)から始めます。すでに大まかな境界が分かっている場合は、[クイックスタート](../quickstart/)へ進みます。
