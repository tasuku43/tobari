## 30 秒で分かる操作

<ol class="home-flow" aria-label="Tobari のレビューフロー">
  <li>
    <strong>Workspace へ入る</strong>
    <span>
      現在のディレクトリからプロジェクトルートと、Context に結び付く論理
      Workspace を選びます。
    </span>
  </li>
  <li>
    <strong>エージェントに作業させる</strong>
    <span>
      HTTP/HTTPS クライアントは Gateway
      を使います。外部への直接経路はありません。
    </span>
  </li>
  <li>
    <strong>未宣言のリクエストが拒否される</strong>
    <span>
      OPA がデフォルト拒否を返し、Gateway は外部の接続先へ接続しません。
    </span>
  </li>
  <li>
    <strong>信頼するホストでレビューする</strong>
    <span>
      秘密情報を含まない保持済みの根拠が、不透明な参照で完全一致の許可対象を識別します。
    </span>
  </li>
  <li>
    <strong>完全一致の許可対象を許可または拒否する</strong>
    <span>ポリシー全体を検証し、途中状態を見せず一括で有効にします。</span>
  </li>
  <li>
    <strong>意図的に再試行する</strong>
    <span>
      Gateway が拒否されたリクエストを代わりに再送することはありません。
    </span>
  </li>
</ol>

## 境界が保護するもの、しないもの

<div class="boundary-comparison home-boundaries">
  <section class="protects">
    <h3>対応する構成で保護するもの</h3>
    <ul>
      <li>選択したプロジェクトのマウント外にあるホストのファイル</li>
      <li>Docker の制御機能とソケット</li>
      <li>別 Workspace のネットワークとホーム</li>
      <li>許可されていない外部への直接通信</li>
      <li>Auth Broker が管理する実物の認証情報</li>
    </ul>
  </section>
  <section class="does-not-protect">
    <h3>意図的に保護しないもの</h3>
    <ul>
      <li>選択したプロジェクトルート内のファイル</li>
      <li>明示的に許可した宛先へ送るデータ</li>
      <li>同じ Workspace 内のプロセス同士</li>
      <li>
        侵害された Docker Engine、ホスト、カーネル、Gateway、OPA、Auth Broker
      </li>
      <li>通常の HTTP/HTTPS 以外のプロトコル</li>
      <li>重なっているプロジェクトルート間のファイル変更</li>
    </ul>
  </section>
</div>

これらをセキュリティ上の主張として扱う前に、[保証と制限](./security/guarantees-and-limitations/)を読んでください。
