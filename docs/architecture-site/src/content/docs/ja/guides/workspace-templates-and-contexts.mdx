---
title: Workspace Template と Context
description: レビュー済みの設定を再利用し、ContextでProjectへ結び付け、置換可能なWorkspaceへ入ります。
---

**Workspace Template** はインストール内で再利用する設定です。
**Context** はcanonical Project rootとTemplateを結び付け、そのProjectの
Policy Memory（記憶した判断）を所有します。**Workspace** はContextに属する
置換可能な実行環境と永続homeです。

## Templateを発見する

```sh
tobari template list --format json
tobari template show --name review --format json
```

名前は読み取り専用の発見表示です。変更操作には発見結果のopaque referenceを
そのまま渡します。

## 作成またはcopy

read-onlyのsource accessとboundedなexact GraphQL endpointを持つTemplateを作成します。

```sh
tobari template create --name review --source-access read-only --graphql-endpoint https://graphql.example.dev:8443/graphql
```

書き込み可能なProject rootには`--source-access read-write`を指定します。省略時の既定値も
`read-write`です。endpointは明示的なportとpathを持つexact HTTPS URLであり、Templateのboundedな
POST policyとして保存されます。次のContext操作には`template list`または`template show`で得たopaque
referenceを使います。

```sh
tobari template show --name default --format json
tobari template copy --from TEMPLATE_REVISION_REF --name review
```

copyはfreshな未公開Template identityと、`base_revision: null`のsource pairを
作ります。generation 1を公開するのは、その後のfreshなPlanとApplyです。
Context、Policy Memory、Workspace、home、credential、attachment、applied
state、default selection、lineageはcopyしません。

## インストールのdefaultを選ぶ

```sh
tobari template list --format json
tobari template default set --id TEMPLATE_REF
```

default selectionが影響するのはbare root entryとbare `status`だけです。
既存ContextやWorkspaceを付け替えません。

## Projectへ結び付けて入る

Project rootから実行します。

```sh
tobari context create --template TEMPLATE_REF
tobari context enter --id CONTEXT_REF
```

通常のdefault作業ではbare `tobari`がdefault Template/Context pairを作成
または再利用し、Workspaceへ入ります。非defaultでは`context list`または
`context show`が返したContext referenceを変更せず`context enter`へ渡します。

```sh
tobari context list --format json
tobari context show --id CONTEXT_REF --format json
tobari context enter --id CONTEXT_REF -- codex exec ...
```

## exact Templateを設定する

```sh
tobari template plan --id TEMPLATE_REF
tobari template apply --plan TEMPLATE_CHANGE_PLAN_REF
```

Apply は完全なimmutable Template revisionを発行します。Runtimeとsession
defaultは後続のentry/session境界、bootstrapは新しいWorkspace homeにだけ
適用されます。

`templates/<template-id>/policy.yaml` は final
`tobari.dev/template-policy/v1` schema で編集します。static policy は closed
な protocol module（HTTP、GraphQL、MCP、Git、OCI）と provider module
（AWS、Kubernetes）に分かれます。各 module は bounded な request fact だけを
投影し、provider の permission catalog を取り込みません。

旧 alpha source が残る installation では、まず desired source だけを移行し、
その後に通常の Template change をレビューします。

```sh
tobari template migration plan --id TEMPLATE_REF
tobari template migration apply --plan TEMPLATE_POLICY_MIGRATION_PLAN_REF
tobari template plan --id TEMPLATE_REF
tobari template apply --plan TEMPLATE_CHANGE_PLAN_REF
```

## 観察と削除

bare `status`はmutationを行わないCWD homeです。

```sh
tobari status --format json
```

非default resourceはexact referenceを使います。

```sh
tobari workspace status --id WORKSPACE_REF --format json
tobari workspace delete --id WORKSPACE_REF --confirm=delete
tobari context delete --id CONTEXT_REF --confirm=delete
tobari template delete --id TEMPLATE_REF --confirm=delete
```

Workspace削除はhomeとnative credentialを削除しますがContext Policy Memoryを
保持します。Context削除にはWorkspace、attachment、research credentialが
残っていないこと、Template削除にはdefault selectionでもContext参照先でも
ないことが必要です。
