Tobari の Go コードは、一方向の依存規則に従います。ドメイン層は純粋な語彙と不変条件を
定義し、アプリケーション層は必要最小限の接点を通して利用者のタスクを解釈します。インフラストラクチャ層は
制御された外部処理を実装し、CLI は全体を組み立てる唯一の構成起点です。

CLI Catalog はヘルプ文の一覧ではなく、すべての公開コマンド契約の正本です。
Gateway、Auth Broker、ランタイム資産には、これに対応するソース境界があります。
編集対象の正本ソースは所有ディレクトリに置き、埋め込み複製はバイト単位で検査する
スナップショットとします。これらの規則により、製品ポリシー、ユースケースの解釈、外部 I/O、表示が、
分離できない一つの実装になるのを防ぎます。

この内容はコントリビューター向けです。[実装技術](../implementation-stack/)を前提とし、通常の Tobari 利用には必須ではありません。

## ドメイン層：純粋な語彙と不変条件

`internal/domain/` は Workspace の識別情報、Context、ポリシー候補と規則、プロバイダーマニフェスト、Broker の結び付き、操作、状態変更の影響、参照、障害、結果スキーマなど、安定した概念を定義します。

ドメイン層は、ファイルシステム、プロセス、Docker、ネットワーク、端末、認証情報の I/O を行いません。このため、安全性や製品上の主張を、副作用に添えたコメントではなく、コンストラクターや検証処理として実行できる形にできます。

例:

- 正規化済みのプロジェクトルートと Context の組み合わせごとに Workspace は一つ
- 完全一致候補の識別情報と不透明な参照の形式
- プロバイダーマニフェストの厳格さと衝突の拒否
- 宣言済み操作と状態変更の契約
- 構造化結果における未指定値と明示値の区別

## アプリケーション層：一つの利用者タスクを解釈する

`internal/app/` は Workspace のライフサイクル、ポリシーのレビューと操作、Context 設定、認証、doctor などのユースケースを担当します。各パッケージが、そのタスクに必要な最小限のポートを定義します。

アプリケーション層のコードはドメイン層の語彙に依存しますが、Docker クライアントやファイルシステム実装には依存しません。たとえばポリシー操作は、根拠の読み取りと検証済みポリシーの有効化をポートに要求しますが、`docker compose` の引数列までは作りません。認証のユースケースは、公開された操作意図を検証してから、秘密情報の入力を、それを扱うインフラストラクチャ層のポートへ渡します。

ポートを利用側の隣に置くことで、インフラストラクチャ層の便利な API が、未宣言の製品権限へ広がるのを防ぎます。

## インフラストラクチャ層：制御された副作用を実装する

`internal/infra/` には、Docker CLI の実行、XDG の状態と設定、ランタイム資産、ルート鍵の保管処理、プロバイダーの読み込み、端末やプロセスの機能、Gateway/Broker の制御、システム診断を担当する具体的な接続実装があります。

インフラストラクチャ層は、Go の構造的型付けによってアプリケーション層のポートを満たせます。欠けた参照を再構築すべきか、そもそもコマンドを公開すべきかといった利用者向けの方針は決めません。ユースケースに無制限の実行手段を渡さず、上限を設けた接続実装を通して処理します。

認証情報を含む型、ルート鍵、保管庫の操作、プロバイダー認証情報の取得、完全一致の HTTP の結び付きは、インフラストラクチャ層が所有します。

## CLI：公開契約と構成起点

`internal/cli/` は、本番用の唯一の構成起点です。インフラストラクチャ層の具体的な接続実装を作ってアプリケーションサービスに注入し、型付けされた引数列を振り分けます。意味を持つ結果の表示と、シグナルの引き渡しも担当します。

`cli.Catalog` は、すべての公開コマンドに対する唯一の正本です。一つの `CommandSpec` から、Tobari は次を導出します。

- パスと名前空間の振り分け
- 概要、結果、役割、操作
- 型付き引数、個数、既定値、上限、依存、競合
- 人間向けヘルプとエージェント向けヘルプ
- 出力形式、エンベロープ、スキーマバージョン、コレクションの配信範囲
- 前提条件と障害
- 完全一致の復旧コマンド
- 参照を生成・消費する関係
- 状態変更の意図、対象の結び付き、影響、完了契約

ハンドラーは競合する別の登録簿を持たず、復旧案内に未検査の引数を追加しません。このサイトの [CLI リファレンス](../../reference/cli/) も、同じ理由で Catalog から生成されます。

## 一つのポリシー操作をレイヤーごとに追う

`policy allow --id pcy_…` を例にします。

1. **CLI Catalog** が、参照に結び付く書き込み、不透明な ID の入力、影響、出力、失敗、復旧を宣言します。
2. **CLI の解析処理** が公開呼び出しとの完全一致を検証し、型付き入力を渡します。
3. **アプリケーション層のユースケース** が現在の根拠から候補を再発見し、参照が現行で、候補一つを一意に識別することを確認します。
4. **ドメイン層** が候補の識別情報、完全一致する学習済み規則の不変条件、状態変更の結果と障害の語彙を定義します。
5. **インフラストラクチャ層** がソースの状態をロックし、Context と集約ポリシーを事前検査します。アトミックに書き込み、監視対象となる完全なポリシーバンドルを公開し、稼働中の OPA が示すリビジョンとの完全一致を確認します。失敗時には元に戻します。
6. **CLI の表示処理** が新しい意味を推測せず、構造化された結果を表示します。

一つのレイヤーだけで処理全体の結果を担当するわけではありません。ただし、責務が依存規則に逆らって外側へ移ることはありません。

## ランタイムの正本と埋め込みスナップショット

Gateway と Auth Broker は Go パッケージではなく Python のランタイムコンポーネントですが、同じ正本規則に従います。

- 編集可能な正本ソースとテストは `gateway/` と `authbroker/` に置く
- バイト単位で検査する埋め込みスナップショットは `internal/infra/runtimeassets/assets/` に置く
- Go バイナリが埋め込みランタイムのバイト列をそのまま実体化する
- 独立して編集できる実装を二つ持たず、ずれを検査で拒否する

OPA ポリシーと Compose のランタイム資産も、埋め込み実装の契約です。生成した集約ポリシーは Context のソースと、Tobari が所有する評価処理から導出します。手書きの振り分け処理をもう一つ持つわけではありません。

## アーキテクチャ制約をテストする理由

`tools/archlint` は依存方向と外部パッケージの import 境界を確認します。`cmd` と `internal/cli` に外部パッケージの import はありません。表示専用の例外を追加するには、完全一致するパス一つについて ADR、ライセンスレビュー、許可リストへの登録、同じ階層を対象にした否定テストが必要です。

Catalog の契約テストは、コマンドの完全性、文法、役割と参照の流れ、出力スキーマ、状態変更の宣言、復旧、エージェント向けヘルプの大きさを検証します。ランタイム資産のテストは、完全一致するマウント、資源制限、イメージの識別情報、正本とスナップショットの一致を検証します。これらの検査により、リポジトリのアーキテクチャをレビュアーの記憶ではなく、違反時に検査が失敗する規則として維持します。

## 失敗時の動作

- ドメイン層の不変条件に違反すると、外部処理より前に失敗します。
- 未知の操作は、安全側に閉じて失敗します。
- 欠けた、または一致しない不透明な操作対象を、アプリケーション層や CLI が再構築することはできません。
- Catalog のコマンド定義が不完全なら、Catalog と検査基盤のテストが失敗します。
- 禁止された依存または外部 CLI パッケージの import は、アーキテクチャ検査に失敗します。
- Python の正本ソースとスナップショットがずれていれば、リポジトリ検査が失敗します。
- 状態変更後の結果を分類できない場合、安全に再試行できるとは報告しません。状態照合を求める障害として扱います。

## 保証と制限

**リポジトリ検査で保証すること:** 強制された依存方向。公開コマンドのメタデータを管理する Catalog が一つであること。タスクが所有するポート。制御された副作用の境界。正本ソースとスナップショットの一致。宣言済みの公開スキーマと状態変更のテスト。

**保証しないこと:** 実装上のバグが一つもないこと。信頼する基盤が侵害された後のランタイム安全性。宣言済み HTTP 契約外にある外部プロバイダー動作の意味的正しさ。アーキテクチャ文書がテストやコードレビューの代わりになること。

## まとめ

ドメイン層は守るべき不変条件を示します。アプリケーション層は最小限のポートを通じて利用者タスクを解釈します。インフラストラクチャ層は上限付きの外部処理を実行します。CLI はシステムを組み立て、Catalog から公開契約を導出します。ランタイムの正本ソース検査により、埋め込み Python 資産が二つ目の実装になるのを防ぎます。
