Workspace は、一つのプロジェクトルートと Context に結び付く論理的な作業環境です。識別情報と永続ホームはランタイムコンテナより長く残り、コンテナやネットワークが失われても、保存済みの状態から作り直せます。

Context は、ランタイム、ポリシー、エージェント設定、認証方式を選ぶ、ホスト管理の設定です。一つのインストール環境では Gateway、OPA、Auth Broker のクラスターを共有しますが、Workspace の識別情報、ホーム、プロジェクトネットワーク、ポリシー上のプリンシパルは共有しません。現在の Context を切り替えても、既存 Workspace が別 Context へ移ることはありません。同じプロジェクトルートに、異なる Context の Workspace を作ることもできます。ネットワーク上の配置は[システム全体像](../system-overview/)で説明します。

## 論理状態とランタイムを分ける

### Tobari と Workspace

内部の製品モデルでは、正規化したプロジェクトルートと安定した Context ID に結び付く、長く残る論理実行環境を **Tobari** と呼びます。利用者がライフサイクル操作や一覧で扱うときの呼び名が **Workspace** です。別々のリソースではありません。

永続的な識別情報は、次の組み合わせで決まります。

- 正規化したホスト上のプロジェクトルート
- 安定した Context ID
- 状態、Docker ラベル、プリンシパルの識別に使う、生成済みの内部 Tobari ID とプロジェクト ID

プロジェクト ID は診断と権限の結び付きに使う内部識別子であり、通常の操作で利用者が入力する対象ではありません。

### Context

**Context** は、安定した不透明な ID と人が読む名前を持つ、ホスト管理の実行設定です。マニフェストは次を参照します。

- 互換性のあるランタイムイメージ
- 読み取り専用のエージェントプロファイル
- selected live bind の immutable `source_access`
- normalized/digested policy preset snapshot と guided/Advanced policy source
- 暗号化した Auth Broker 保管庫とは別に保存するプロバイダー設定

Context マニフェスト自体には、ルート鍵、Auth Broker が管理する認証情報の本体、保管庫の内容は含まれません。**現在の Context** は、コマンドで `--context` を省略したときの既定値です。既存 Workspace の権限や結び付きを変更するものではありません。

### クラスター

インストール環境ごとの **クラスター** には、Gateway、OPA、ロック状態の Auth Broker が一つずつあります。さらに、`control` と `egress` のネットワーク、全 Context の設定から生成したポリシーとプロバイダーの読み取り専用データ、プリンシパル登録簿、CA のライフサイクルが含まれます。

すべての Workspace がこのクラスターを共有します。共有サービスを使っても、プロジェクトの識別情報は混ざりません。Gateway はリクエストごとに Context とプロジェクトのプリンシパルを導出し、OPA は安定した Context ID を使って対応するポリシーへ振り分けます。

### ランタイムイメージとコンテナ

**ランタイムイメージ**は OS、ツール、エントリーポイント、ランタイム API を提供します。**ランタイムコンテナ**は、ある時点の Workspace でプロセスを実行するための実体です。どちらも Workspace の識別情報や寿命を決めません。

Tobari は、マウント、保護済みネットワーク、CA 信頼環境、実行ユーザー、セキュリティとリソースの上限、ヘルスチェック、明示的な `sleep infinity` を指定してコンテナを作ります。イメージの `CMD` が Workspace の寿命を決めることはありません。構成のずれやコンテナの消失が起きても、論理 Workspace とホームを残したままコンテナを作り直せます。

## 現在のディレクトリから Workspace を選ぶ

Tobari は、保存状態や Docker を扱う前に、ホスト上の現在の作業ディレクトリを正規化します。

1. 選択中の Context に完全一致する登録済みルートがあれば、その Workspace を直接再利用できます。
2. 現在のディレクトリを含む上位の登録済みルートが一つ以上あれば、対話型の `tobari` は近い順に有効な候補を表示します。
3. 利用者は、既存 Workspace の選択、現在のディレクトリでの明示的な作成、キャンセルのいずれかを選びます。
4. Tobari は入れ子の Workspace を暗黙に作りません。

`status` と `delete` は、明示した Context または現在の Context の中から、現在のディレクトリに最も近い Workspace を特定します。利用者が Docker の名前や内部 ID を管理する必要はありません。

## 同じプロジェクトルート、異なる Context

`/work/payments` が Context `default` の Workspace にマウントされているとします。Context `review` で実行すると、プロジェクトルートと Context ID の組み合わせが異なるため、同じ正規化済みルートに二つ目の Workspace を作れます。

二つの Workspace では、次が別々です。

- 安定したプロジェクト ID
- ホームと、ツールが管理する認証状態
- ランタイムコンテナと内部ネットワーク
- プロジェクトのプリンシパル
- Context とプロジェクトに限定された学習済みルールと Auth Broker ハンドル

一方、`/work/payments` 以下の live file は意図的に共有されます。各 Context は read-only または
read-write source access を選べますが、read-only Context も host/read-write Context の変更を観測
します。Tobari は overlay、checkout clone、root lock、filesystem integrity isolation を追加しません。

## Context とランタイムを変更する

`context use --name review` が変更するのは、Context を省略したコマンドで使う既定値だけです。既存 Workspace の状態や Context は変更せず、Docker を起動したり、新しい集約ポリシーを有効化したりもしません。

既存 Workspace は、保存済みの Context ID に結び付き続けます。Context のランタイムを再ビルドすると、その Context が要求するイメージが変わります。次に Workspace へ入るとき、ランタイムコンテナをそのイメージへ合わせますが、識別情報とホームは残ります。カスタムイメージが見つからない、または互換性がない場合は、ランタイムを変更する前に失敗します。

## 失敗時の動作

- 同じ正規化済みルートと Context ID を持つ Workspace の重複作成は拒否されます。並行して作成した場合も、成功するのは一つだけです。
- 親ディレクトリの候補が複数ある場合は、明示的に選びます。表示順に権限上の意味はありません。
- 永続的なルート索引があるのにインスタンス状態がない場合は、`incomplete` と報告します。Workspace へ入る処理は欠けた状態を推測せず、完全一致する対象の `delete` が後片付けの経路になります。
- ランタイムコンテナまたはネットワークがない場合は、次に Workspace へ入るときに調整します。
- イメージが見つからない、または互換性がない場合は、ランタイムを作成・交換する前に失敗します。
- 現在の Context を変更しても、既存状態が暗黙に移動することはありません。

## 保証と制限

**保証すること:** 安定した Context とプロジェクトの識別情報は、コンテナの再作成後も維持されます。完全一致するプロジェクトルートと Context の組み合わせごとに Workspace は一つです。Context の既定値と既存 Workspace の権限は別です。ランタイムの `CMD` は、Tobari が定める寿命の契約を置き換えられません。

**保証しないこと:** 同じルートまたは重なるルート間のファイルシステム分離。プロジェクトディレクトリを移動またはコピーした後の自動推測。任意のカスタムイメージの信頼性。設定済みのローカルイメージやカスタムイメージの自動取得。

## まとめ

Workspace は永続する論理的な作業環境です。Context は、そこへ結び付くホスト管理の設定と識別情報です。クラスターは共有の強制基盤です。ランタイムイメージが作業環境を提供し、ランタイムコンテナは必要に応じて作り直せます。
