## release surface の所有権

agent CLI はネイティブ認証状態を Workspace にマウントした永続 Context Home 内に
作成・保存します。Tobari は host credential を継承・コピーせず、release surface には
Tobari 所有の認証 command や credential service もありません。

同じ Context の全 sibling Workspace とプロセスはその状態を読めます。別 Context は別の Home を
持ちます。Workspace 削除後も置換用に tool-owned state を保持し、exact Context
delete で削除します。

## post-policy forwarding

Gateway は認証情報を policy identity ではなく secret request data として扱います。
Authorization、API key、cookie を OPA input と audit から除外し、通常の exact HTTP
effect を OPA に問い合わせ、allow 後だけ元の値を渡します。deny では DNS も
upstream connection も実行しません。

したがって login と permission は独立しています。

- native login は policy rule を追加しません。
- allow は credential の作成や refresh をしません。
- policy が許可すれば same-Context sibling Workspace の process は認証済み effect を利用できます。
- Tobari は `claude`、`codex` などの process name から権限を推測しません。

## agent-ready の login effect

pinned agent-ready compatibility baseline は Claude の hello/token/profile/roles と
Codex の browser/device token effect を exact に含みます。Claude regression は native token exchange 後も
subscription と rate-limit classification を含む provider profile metadata を保持
します。

## security limit

Workspace ネイティブ認証は host と別 Context Home を保護しますが、同じ Context
Home を共有する sibling Workspace 間での process-level secret isolation ではありません。認証済み request
の送信先は exact network policy が制御します。
