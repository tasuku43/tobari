Tobari は、ネットワーク構成そのものを強制境界の一部に使います。サポートされる
構成では、各 Workspace が参加するのは専用の Docker internal network だけです。
プロジェクト側のネットワークと外向き通信側の両方に interface を持つ component
は Gateway だけなので、proxy 設定を外しても public Internet への別経路は生まれません。

プロジェクト通信、ポリシー制御、外向き通信は三つの network scope に分かれます。
必要な scope を横断するのは Gateway であり、OPA と Auth Broker の接続範囲はさらに
狭くなっています。許可されたリクエストは Gateway から外へ進み、Gateway または
OPA の障害時には経路が閉じます。以下の主体は[メンタルモデル](../mental-model/)で紹介しています。

## 三つのネットワーク範囲

### Workspace ごとの専用ネットワーク

Tobari は logical Workspace ごとに Docker の `internal` property を持つ network 一つを作ります。work container が参加するのはその network だけです。Gateway は alias `gateway` で接続されます。

container は `http://gateway:8080` を指す大文字・小文字の HTTP/HTTPS proxy variable、空の `NO_PROXY` value、Tobari CA bundle を受け取ります。これらの setting は supported client を intended path へ導きますが、より強い control は network topology です。client が variable を削除しても Docker-provided external route はありません。

### 内部制御ネットワーク一つ

OPA は shared `control` network に参加し、project network や egress には参加しません。そのため Workspace process は OPA policy endpoint を直接呼べません。

Gateway も control に参加し、固定 OPA endpoint 一つを呼びます。Auth Broker は control と egress に参加しますが TCP listener を公開しません。host command と Gateway は controlled mount と fixed operation を通じ、それぞれ別の Unix socket へ到達します。どちらの socket も Workspace/OPA から利用できません。

Broker-private companion socket は Auth Broker container namespace 内だけに存在し、authenticated reverse `docker exec -i` session 一つで resident trusted-host companion へ bridge されます。Workspace へ mount されず、host に publish されません。

### 外向き通信ネットワーク一つ

Gateway は `egress` に参加し、allowed destination を resolve/connect します。Auth Broker が egress を使うのは、exact US1 token endpoint 一つに対する compiled post-policy Datadog refresh plan だけです。interactive GitHub/AWS/Datadog acquisition は Broker egress ではなく、信頼するホストの fixed driver から直接行います。work container はこの network に参加しません。

## 許可されるリクエストの順序

  title="ネットワーク経路と fail-closed の動作"

重要な順序は次のとおりです。

1. Workspace の dedicated network から traffic が入る
2. Gateway が host-issued principal を確立する
3. Gateway が body-free normalized input で OPA へ一度問い合わせる
4. allow 後にだけ Gateway が upstream address を resolve/pin する
5. Gateway が upstream connection 一つを開き、request を stream する
6. Gateway が bounded secret-free audit metadata を記録する

application-layer automatic retry はありません。redirect は独立した request で、再び authorization を受けます。

## 同じシステム内の信頼境界

<ConceptDiagram name="trust-boundaries" />

Workspace と upstream は untrusted です。host、Docker execution substrate、Gateway、OPA、Auth Broker、owner-controlled state は trusted enforcement infrastructure です。ここで「trusted」は Tobari の claim がそれらに依存するという意味で、bug がないという意味ではありません。

## 回避を試みる具体例

### process が proxy 設定を解除する

direct TCP connection を試せますが、internal project network に external route がないため失敗します。Tobari は network control を迂回するよう transparent redirect しません。

### process が `opa:8181` を呼ぶ

OPA は Workspace network に接続されていないため、container から name/service へ到達できません。

### process が別の Workspace を狙う

各 Workspace の internal network は別です。peer route はありません。Gateway は両方に参加しますが、Workspace 間の general router として動きません。

host file root は別の boundary です。二つの Workspace が同じまたは重なる project root を意図的に mount する場合があります。network、home、principal、learned rule は分離されますが、overlapping host file への書き込みは両方から見えます。

## 失敗時の動作

- **Gateway が利用不能:** 設定済みの proxy が接続を受けられません。外部への直接経路は変わらずありません。
- **OPA が unavailable、slow、non-200、oversized、malformed、incomplete:** Gateway は `503 policy_unavailable` を返し、resolve/upstream connection を行いません。
- **aggregate policy に unknown Context:** fixed OPA router は deny し、current/default Context へ fallback しません。
- **unsafe dotted-host DNS result:** Gateway は non-global address を拒否し、別 authority を暗黙に選びません。これは upstream/proxy failure であり stable public JSON fault code ではありません。
- **Workspace container/network が missing:** 次の entry で logical state から runtime resource を reconcile します。Docker resource loss で logical Workspace は消えません。

## 保証と制限

**supported topology で保証すること:** direct Workspace egress がないこと。Workspace から OPA、Broker socket、Docker socket、別 project network への route がないこと。policy failure 後に upstream を試さないこと。shared service CPU、memory、PID、Docker log が bounded であること。

**保証しないこと:** Workspace 間での fair bandwidth/shared-service capacity、host/Docker/kernel/Gateway/OPA/Broker compromise 後の保護、selected project root 下の disk quota、non-HTTP protocol の general network policy、overlapping selected root 間の filesystem isolation。

## まとめ

proxy variable は client を導き、Docker network attachment が supported route を enforce します。Gateway が project network を policy/egress へ bridge します。OPA は egress なしで判断し、Auth Broker は Workspace networking へ公開されません。
