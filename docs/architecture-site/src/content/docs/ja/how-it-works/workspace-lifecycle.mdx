Workspace の寿命は、接続中のシェルより長く続きます。`exit` が終了するのは実行
セッションだけです。論理 Workspace、ホーム、ランタイムの記録、Context との結び付きは
次回の入室のために残ります。`delete` は一つの論理 Workspace と、その所有する状態を
削除します。クラスターの停止は別の操作で、すべての Workspace を削除した後にだけ実行できます。

コンテナやネットワークを失っても、論理 Workspace まで自動的に失われるわけでは
ありません。入室時に、交換可能なランタイム状態を永続記録と照合して修復します。
`delete --force` の目的はより限定されており、`cluster down --purge` は Workspace の削除でも
認証情報のログアウトでもありません。このライフサイクルで使う識別情報は
[Workspace、Context、クラスター](../workspace-context-cluster/)で説明しています。

## 状態変化を順番に追う

### 存在しない → 接続中

選択したディレクトリから `tobari` を実行すると、正規化済みルートと Context に対応する既存 Workspace を選ぶか、明示的に作成します。作成時には識別情報とホームを永続記録へ保存し、専用ネットワークとコンテナを調整します。さらに Gateway と Workspace の閉じたネットワークガードを適用し、両方の正確なエンドポイントを登録し、利用可能になるまで待ってから、対話型の `docker exec` シェルを開始します。

接続中のシェルは一時的なプロセス状態であり、Workspace の寿命を決めるプロセスではありません。

### 接続中 → 切り離されるが存在は続く

シェルの `exit`、完全一致するエージェントコマンドの終了、子プロセスの 0 以外での終了が止めるのは、実行中のプロセスだけです。Tobari は次を保持します。

- ルート索引とインスタンス記録
- 永続的な Context の結び付きとプロジェクト ID
- Workspace ごとのホームと、ツールが所有するログイン状態
- ランタイムコンテナと専用ネットワーク
- Context/project に限定された学習済みポリシー
- Context が所有する Broker 認証情報と、このプロジェクトの現在のハンドル投影

永続化された「一時停止」状態はありません。「切り離された」とは、接続中の実行セッションが観測されないという意味です。論理 Workspace は存在し続けます。

### 切り離された状態 → 再び接続中

次に `tobari` で入室すると、同じ論理記録を特定し、接続する前にランタイムの構成ずれを調整します。識別情報とホームは変えません。必要に応じて、コンテナまたはネットワークの再作成、Context が要求するイメージへの更新、現在のプロジェクトに結び付く Broker ハンドル投影の再発行、通信主体登録の修復を行います。

### 切り離された状態 → 存在しない

`delete` は、まず接続中の実行セッションがないことを確認します。所有者、役割、プロジェクトラベルが完全に一致することを検証してから、その Workspace のコンテナとネットワークだけを削除します。その後、ルート索引、インスタンス状態、ホーム、プロジェクト認証の投影、登録簿の項目を削除します。マウントしたルート内のプロジェクトファイルは決して削除しません。

### 接続中 → `--force` で存在しない

通常の削除は、接続中の Workspace に対して実行できません。`delete --force` が解除するのは、接続中のセッションを守る検査だけです。Docker の所有権と識別情報の検査は緩めず、対象範囲も広げず、プロジェクトファイルの削除も許可しません。

## ランタイムの消失と構成ずれ

Workspace の存在を決めるのは論理状態であり、Docker の検査結果ではありません。

- **コンテナの消失:** 次の入室時に互換性のあるコンテナを作り、既存のプロジェクトルートとホームを再びマウントします。
- **ネットワークの消失:** 次の入室時に内部ネットワークを作り直し、Gateway を接続します。両方のガードを再適用し、新しいエンドポイントの結び付きを書き込んでから、利用可能な状態にします。
- **Context ランタイムの再ビルド:** 次の入室時に要求されるランタイムの識別情報と比較し、必要な場合だけプロジェクトコンテナを作り直します。
- **資源またはセキュリティ契約の変更:** 望ましい構成のハッシュが変化し、調整を行います。
- **ルート索引はあるがインスタンス状態がない:** `incomplete` であり、内容を推測してよい状態ではありません。入室は失敗し、完全一致する対象を削除してクリーンアップします。

永続ジャーナルが中断された作成と削除を扱うため、一部だけ残ったファイル群が、暗黙に二つ目の Workspace として扱われることはありません。

## クラスターのライフサイクルは別に管理する

論理 Workspace のインスタンスが一つでも残っている間、`cluster down` は拒否されます。先にすべての Workspace を削除してください。

その後の違いは次のとおりです。

| 操作                   | 削除するもの                                                                   | 保持するもの                                                           |
| ---------------------- | ------------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| `cluster down`         | 共有 Gateway、OPA、Auth Broker コンテナと一時的な共有ネットワーク／投影        | Context、ポリシーソース、暗号化保管庫、ルート鍵、Gateway CA ボリューム |
| `cluster down --purge` | 同じ共有ランタイム資源、共有 CA ボリューム、有効なポリシーバンドルのボリューム | Context、ポリシーソース、暗号化保管庫、インストール用ルート鍵          |

`--purge` の実行後にクラスターを起動すると、新しい共有 CA 状態が作られます。この操作は、プロバイダーの認証情報を失効させたり、暗号化保管庫を削除したりするものではありません。ローカルの認証情報削除とハンドルの無効化には `auth logout <provider>` を使います。

## 具体例

`/work/service` の Workspace に入り、ツール固有のログインを行ってから `exit` したとします。

1. ツールのログインファイルは、その Workspace の永続ホームに残ります。
2. プロジェクトファイルと論理記録は残ります。
3. 後で入り直すと、同じ Workspace とホームを再利用します。
4. 途中でコンテナが手動削除されていても、Tobari が再作成し、そのホームを再びマウントします。
5. 切り離された状態で `delete` すると、Workspace のホームは削除されます。プロジェクトルートは残ります。

## 失敗時の動作

- 接続中の実行セッションがあると、通常の `delete` は削除前に失敗します。
- 所有者ラベルが不正または欠落している場合は、資源を削除しません。
- ランタイムに互換性がない場合は、プロジェクト資源を変更する前に失敗します。
- コンテナやネットワークを失っても、論理状態を暗黙に削除しません。
- インスタンス記録が残る間、`cluster down` は失敗します。
- 中断した状態変更の復旧には、完全一致するライフサイクルコマンドが必要な場合があります。完了したとは推測しません。
- 状態変更が成功した後のキャンセルは、状態変更の完了境界を通して報告します。安全に再実行できるような結果には見せません。

## 保証と制限

**保証すること:** セッションからの退出は削除ではありません。削除は完全一致する一つの Workspace だけを対象とし、プロジェクトファイルは保持します。ランタイム資源は論理的な識別情報を変えずに再作成できます。`--purge` をログアウトとして扱うことはありません。

**保証しないこと:** 手動削除したプロジェクトファイルまたは Workspace ホームの復元。ルートを移動した後の自動移行。Workspace 削除後のツール固有ログインの保持。ローカルでログアウトした後に、リモートのプロバイダー側で認証情報を失効させること。

## まとめ

接続中のセッション、論理 Workspace、Docker ランタイム、共有クラスター、Context の認証状態は、それぞれ寿命が異なります。退出には `exit`、Workspace の削除には `delete`、削除後の共有サービス停止には `cluster down`、プロバイダー認証情報の削除には `auth logout` を使います。
