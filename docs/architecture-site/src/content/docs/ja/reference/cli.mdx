公開 CLI の正本は Go の `cli.Catalog` です。作業別の入口からコマンドを絞り込み、各コマンドの完全な仕様を確認できます。入出力、前提条件、状態変更、障害、復旧方法は Catalog から直接生成しており、文書側で複製していません。

<CliTaskIndex />

<details>
<summary>コマンド仕様の読み方</summary>

各コマンドは、一意のコマンドパスと一つの完全な仕様を持ちます。

| 項目                              | 意味                                                                         |
| --------------------------------- | ---------------------------------------------------------------------------- |
| 達成結果（Outcome）               | コマンドが完了させる利用者の作業                                             |
| 役割（Role）                      | `utility`、`discover`、`act`                                                 |
| 作用（Effect）                    | `read`、`create`、`write`。未定義の作用は不正                                |
| 入力（Inputs）                    | 個数、省略時の動作、範囲、依存関係、競合条件を含む、型付きの位置引数とフラグ |
| 出力（Output）                    | 形式、フィールド、JSON の構造とスキーマバージョン、配信方式、収集範囲        |
| 前提（Prerequisites）             | 操作が成功する前に存在していなければならない状態                             |
| 障害（Failures）                  | 安定した `kind` と `code`、再試行可否、Catalog に宣言された次の操作          |
| 参照値（References）              | 検出操作が生成し、実行操作が変更せずに受け取る不透明な値                     |
| 変更操作契約（Mutation contract） | `create` または `write` の意図、対象との結び付き、影響、確定した結果         |

`utility` は単独で完結する作業を実行します。`discover` は候補を返し、必要に応じて
不透明な参照値も返します。`act` は対象を一つ変更します。実行操作は、必須の参照値を
そのまま受け取るか、コマンド自身が所有する固定対象を一つ使います。識別子を再検出、
デコード、再構築しません。

ルートのエージェント向けヘルプは、小さな機能索引です。完全な契約を取得するには、
コマンドまたは名前空間を完全一致で指定します。

```console
tobari help --format agent
tobari help policy --format agent
tobari help policy allow --format agent
```

ハイフンで始まるフラグ値には equals 形式を使います。ハイフンで始まる位置引数は、
位置引数専用マーカーの後に置きます。以下の生成済み呼び出し構文が、ビルド対象
コミットにおける正本です。

</details>

<details>
<summary>障害と復旧の規則</summary>

通常のコマンド失敗は、テキストまたはエラー JSON のスキーマ 1 で表示できます。
`kind` は大まかな復旧分類、`code` はプログラムが完全一致で判定する条件です。
`retryable: true` は再試行を検討できるという意味であり、変更操作を安全に再実行できる
証明ではありません。変更操作が中断された場合は、コマンドの結果契約と現在の状態を
照合してから再試行してください。

復旧コマンドも Catalog から生成されます。完全一致するコマンドパス、または
`help <exact-path-or-namespace>` です。接続先のエラーに含まれる信頼できない文字列を
付け足してはいけません。

`invalid_fault_contract` は形式不正の構造化障害を置き換え、
`undeclared_fault_contract` は Catalog の宣言と一致しないコマンド障害を置き換えます。
どちらも通常のプロバイダー応答ではなく、Tobari の契約不備を示します。

</details>

<details>
<summary>このリファレンスの制限と根拠</summary>

- 安定した機械向けフィールドを変えずに、人向けの文言を改善する場合があります。
- Catalog が記述するのはサポート対象の公開 CLI です。ベンダーの未加工ルート、Docker
  コマンド、Broker プロトコル、任意の HTTP 呼び出しは公開しません。
- 生成したコマンド契約が、外部サービスを利用可能にしたり、ネットワーク権限を
  与えたりはしません。
- 完全な配信方式は、プロバイダーの全履歴を網羅するという意味ではありません。
  収集範囲は別に宣言します。
- 通常のソースビルドはバージョン `dev` を報告します。リリース処理がリリース番号と
  ソースコミットを埋め込みます。
