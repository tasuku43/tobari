このリファレンスには、すべての公開 Tobari command と、その正確な input、
output、effect、reference flow、mutation contract、fault、recovery action を掲載します。
正本は Go の `cli.Catalog` です。以下の内容は Tobari の machine-readable help
を通じて生成され、別の command list として保守されていません。

summary view では user outcome から command を選べます。required input、default、
conflict、prerequisite、output coverage、action が consume する opaque reference
を確認するときは complete contract を開いてください。これらの用語が初めてなら、
machine contract の前に [mental model](../../how-it-works/mental-model/) を読んでください。

## 契約の読み方

すべての command は一つの exact path と一つの complete specification を持ちます。

| Field             | 意味                                                                                                 |
| ----------------- | ---------------------------------------------------------------------------------------------------- |
| Outcome           | command が完了させる user task                                                                       |
| Role              | `utility`、`discover`、`act`                                                                         |
| Effect            | `read`、`create`、`write`。unknown effect は invalid                                                 |
| Inputs            | cardinality、omission behavior、bound、dependency、conflict を含む typed positional argument と flag |
| Output            | format、field、JSON envelope/schema version、delivery mode、collection coverage                      |
| Prerequisites     | operation が成功する前に存在すべき state                                                             |
| Failures          | stable kind、code、retryability、Catalog-owned next action                                           |
| References        | discovery が生成し、action が変更せず consume する opaque value                                      |
| Mutation contract | create/write の intent、target binding、impact、confirmed outcome                                    |

`utility` は self-contained task を実行します。`discover` は candidate と、必要なら opaque reference を返します。`act` は target 一つを変更します。action は required opaque reference を exact に consume するか、command-owned fixed target 一つを使います。identifier を rediscover/decode しません。

root agent-help view は意図的に小さな capability index です。complete contract には exact command または namespace selector を使います。

```console
tobari help --format agent
tobari help policy --format agent
tobari help policy allow --format agent
```

dash-prefixed flag value は equals form を使います。dash-prefixed positional value は positional-only marker の後に置きます。以下の generated invocation grammar が build commit の authority です。

## 障害と復旧の規則

normal command failure は text または error JSON schema 1 で render できます。machine form は次の形です。

```json
{
  "schema_version": 1,
  "error": {
    "kind": "canceled",
    "code": "operation_canceled",
    "message": "The operation was canceled.",
    "retryable": true,
    "retry_after": null,
    "next_actions": [
      {
        "command": "doctor",
        "reason": "Retry when the caller is ready."
      }
    ]
  }
}
```

`kind` は broad recovery class、`code` は exact programmatic condition として扱います。`retryable: true` は retry の検討を許可しますが、mutation replay が安全だと証明しません。`retry_after` は rate-window evidence で、logical replay safety とは独立しています。interrupted mutation では、retry 前に command outcome contract を確認して state を reconcile します。

recovery command は Catalog から来ます。exact command path または `help <exact-path-or-namespace>` です。upstream error の untrusted text を追加しないでください。

二つの fail-closed diagnostic が fault boundary 自体を保護します。`invalid_fault_contract` は malformed structured fault を置換し、`undeclared_fault_contract` は Catalog declaration と一致しない command fault を置換します。これらは ordinary provider response ではなく Tobari contract defect を示します。

## このリファレンスの制限

- stable machine field を変えず human wording が改善される場合があります。
- Catalog が記述するのは supported public CLI です。raw vendor route、Docker command、broker protocol、arbitrary HTTP call は公開しません。
- generated contract は command behavior を説明します。external service の availability や network permission は与えません。
- complete delivery mode は exhaustive provider history を意味しません。collection coverage は別に宣言します。
- source build は通常 version `dev` です。release automation が release version/source commit を inject します。この page は release number を発明しません。

## まとめ

Catalog は public CLI の source of truth です。generated help が typed grammar、output、reference flow、mutation fact、failure、recovery を公開します。site はその contract を読み、二つ目の registry を作りません。

## 理解を確認する

copied command name list だけでは CLI reference として不十分な理由を説明できるはずです。

<details>
  <summary>
    <code>policy allow</code> が opaque reference を受け取る
    するのはなぜですか？
  </summary>
  discovery と action を分離するためです。reference は action に
  rediscover/decode/reconstruct させず、host-side action を reviewed candidate
  一つへ bind します。
</details>

<details>
  <summary>
    <code>retryable: true</code> なら、失敗した変更操作
    はすべて繰り返して安全ですか？
  </summary>
  いいえ。fault を分類しているだけです。mutation
  がすでに完了した可能性があるため、replay 前に structured outcome と current
  state を reconcile する必要があります。
</details>

<details>
  <summary>argument の既定値と競合条件はどこで確認しますか？</summary>
  command の Catalog input から生成される exact-command agent help です。root
  help index はその detail を意図的に省略します。
</details>
