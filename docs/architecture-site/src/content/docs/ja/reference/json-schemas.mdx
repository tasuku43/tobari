Tobari は、用途の異なる複数の JSON 形式を、個別にバージョン管理します。公開 CLI のレポート、保存する Context マニフェスト、Gateway のポリシー入力、Auth Broker のフレームは、関連する状態を扱っていても別の契約です。スキーマ番号は、対象となる形式の名前と組み合わせて初めて意味を持ちます。

各形式の正本は、それを所有する Catalog の項目、パーサー、またはプロトコル実装です。このページは、下部に表示する製品スナップショット時点の契約をまとめます。

フィールドの正確な内容、任意項目、出力形式、対応するコマンドは、[CLI リファレンス](../cli/)から確認できます。利用側は、エンベロープと `schema_version` の組み合わせで形式を選んでください。別のエンベロープに同名のオブジェクトがあっても、そのフィールドを流用できるとは限りません。

## Context の保存形式と表示形式は別の契約

```text
Host configuration
  contexts/<name>/context.json
  Context manifest schema 5

CLI presentation
  {"schema_version": 8, "context": ...}
  public Context report schema 8
```

公開レポートには、ランタイム、クラスター、シェル、Git、秘密情報を含まない認証状態の解釈が加わります。`context.json` の内容をそのまま表示したものではありません。

## 主なホスト上の永続化契約

| 状態                                         | 現在の契約                   |
| -------------------------------------------- | ---------------------------- |
| Context マニフェスト                         | スキーマ 5                   |
| ルートインデックスと Workspace インスタンス  | スキーマ 2                   |
| 共有クラスター状態                           | スキーマ 3                   |
| プロジェクトプリンシパル登録情報             | スキーマ 2                   |
| Guided ポリシーデータ                        | `tobari.schema_version` 2    |
| 集約ポリシー投影マーカー                     | スキーマ 1                   |
| 所有者管理のプロバイダーマニフェスト         | スキーマ 1                   |
| レビュー済み組み込みプロバイダーマニフェスト | スキーマ 1 または 2          |
| 正規化済みプロバイダー投影                   | スキーマ 2                   |
| 暗号化した Context 保管庫                    | エンベロープ 1、ペイロード 2 |
| Workspace 認証ファイル登録情報               | スキーマ 1                   |
| ベースランタイムのメタデータ                 | スキーマ 1                   |

Context 保管庫には、型付きの静的認証情報、AWS の不透明な状態、Datadog OAuth 状態、OpenAI Codex OAuth 状態、Anthropic の静的トークン状態、リビジョン、結果が不明な処理の永続バリア、未加工のハンドルを保存できます。公開 `auth` エンベロープが状態を要約しても、これらの内部値が公開出力になるわけではありません。

## Gateway、OPA、監査、Broker の契約

| 境界                               |           現在の契約 | 重要な規則                                                                                                             |
| ---------------------------------- | -------------------: | ---------------------------------------------------------------------------------------------------------------------- |
| Gateway の認証情報設定             |           スキーマ 2 | 管理対象の投影情報を含みますが、ポリシー権限は含みません。                                                             |
| Gateway → OPA の判断入力           |           スキーマ 5 | ホストから導出したプリンシパルと正規化済み HTTP 属性。通常の本文とクライアントの秘密ヘッダーは含みません。             |
| Guided／Advanced のソースポリシー  |     ソーススキーマ 4 | ソーススキーマ 3 は移行時だけ受け入れ、集約結果はランタイムスキーマ 5 になります。                                     |
| Gateway の監査行                   |           スキーマ 2 | 上限を設けた、秘密情報を含まない判断記録です。                                                                         |
| 学習可能な拒否の案内応答           |           スキーマ 1 | 固定されたホスト側レビュー案内。候補 ID、クエリー、本文、秘密情報を含みません。                                        |
| Broker の制御プロトコル            |           スキーマ 1 | ホスト制御ソケット上の、上限付き改行区切り JSON です。                                                                 |
| Broker のランタイムプロトコル      |           スキーマ 1 | 秘密情報を含まない検査後、許可済み通信に対して、静的解決、Datadog／OpenAI トークン処理、AWS 署名のいずれかを返します。 |
| 非公開ホストコンパニオンのフレーム |           スキーマ 1 | 認証済みで方向を固定し、厳密な順序で AWS の組み込み処理だけを運びます。                                                |
| Workspace の Broker ハンドル       | ハンドルバージョン 1 | 不透明な `tobari-h1_…` のバイト列です。内容を権限として解釈しません。                                                  |

OPA が返すのは判断です。外部接続を所有するのは Gateway であり、判断を取得できない、または形式が不正な場合は安全側に閉じます。

## 互換性の規則

- 未知のバージョンは未対応として扱い、既知の新しい形式へ自動変換しないでください。
- 対象の契約が区別する場合は、フィールドが存在しない状態と、明示的な空文字・ゼロ・偽を区別してください。
- 不透明な参照値とハンドルは正確なバイト列として扱い、正規化、短縮、復号、再構築をしないでください。
- 表示名、配列の順序、インデント、近くにある情報から識別関係を推測しないでください。
- 内部状態ファイルを連携用インターフェースにせず、公開 CLI を使ってください。
- 変更結果を確定できない場合は、再実行する前に、正本となる status またはレポートを確認してください。

## 障害時の動作

形式不正、上限超過、危険な値、未対応バージョンは、それを所有する読み取り処理が拒否します。互換性は形式ごとに決まります。古い Context マニフェストを移行できても、古い Broker フレームや将来の公開 CLI エンベロープを受け入れられるとは限りません。

## まとめ

バージョンは、一つの名前付き形式に属します。公開 CLI、永続状態、ポリシー入力、監査記録、Broker プロトコルは、個別に解釈し、個別に移行してください。
