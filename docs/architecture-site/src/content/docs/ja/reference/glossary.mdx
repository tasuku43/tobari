この用語集では、Tobari の実行、ネットワーク、ポリシー、認証、状態、CLI 契約で使う語を定義します。論理状態、ホスト設定、共有の強制基盤、ランタイム、agent CLI のログイン、通信許可は、それぞれの管理主体が異なります。

## 実行と所有

### Tobari

製品、実行ファイル、所有主体を表す名前です。Tobari は Workspace と、インストール内で共有する Gateway と OPA を準備・管理します。

### Workspace

Context が所有する、置き換え可能な隔離インスタンスです。安定した Workspace ID、専用 home、最後に成功した AppliedEntry、実行時リソースを持ちます。セッション終了は Workspace の削除ではなく、Workspace の削除後も Context と Policy Memory は残ります。

### プロジェクトルート

Context が所有する正規化済みホストディレクトリです。結び付いた Workspace Template の不変 `source_access` に従って Workspace へマウントされます。Workspace 内のプロセスによるファイル変更を Tobari はスナップショットやオーバーレイで保護しません。

### Workspace Template

インストールが管理する、再利用可能な実行設定です。安定した ID と完全な不変 revision を持ち、source/network Boundary、baseline policy、exact Runtime binding、entry/session/creation default を所有します。Project binding と remembered decision は所有しません。

### Context

一つの正規 Project root と一つの Workspace Template ID を結ぶ、永続かつ不変の binding です。Policy Memory を所有し、Workspace の置換や削除後も残ります。公開 name/default selector はなく、非既定の操作は discovery が返す exact `context` reference を使います。

### Policy Memory

一つの Context が所有する remembered decision の完全な不変 revision です。Workspace の置換後も残り、Template copy では複製されず、Template の固定 Boundary を広げません。

### current Workspace Template

bare root entry と bare `status` が使うインストール既定の Workspace Template です。変更しても既存 Context や Workspace は結び直されず、request authority にもなりません。

### クラスター

共有 Gateway、OPA、ネットワーク、CA ボリューム、ポリシー投影の集合です。各 Context は結び付いた Template baseline と Policy Memory を提供し、クラスターは有効な完全集合を強制します。

### Workspace home

Workspace が所有する独立した書き込み可能ホームです。agent CLI はここに自分のログイン状態を保存します。セッション終了やコンテナ再作成後も残り、Workspace の `workspace delete` で削除されます。

### ランタイムイメージ

ツールとルートファイルシステムを供給する OCI イメージです。標準 Runtime は固定 recipe、管理対象 Runtime は成功した semantic source revision に結び付きます。公開 action authority は opaque Runtime reference であり、Docker tag や image ID ではありません。

### 作業コンテナ

Runtime image から一時的に実体化した Docker resource です。消失または置換されても、論理 Workspace、Context binding、authority envelope、Workspace home は残ります。container の存在だけから論理 Workspace を発明しません。

### attached session

信頼するホストの `tobari` entry と一つの Workspace 内 child process を結ぶ実行中セッションです。`exit` はこの session を終えるだけです。attached session がある間の delete は拒否され、`--force` はその exact guard だけを意図的に上書きします。

## リクエストの強制

### Gateway

Workspace の HTTP 通信を受け、必要なら Workspace 側 TLS を終端し、ホストが発行した Workspace 識別情報を導出します。認証情報の値を OPA と監査から除外し、OPA の許可後に元の値を使って別の接続先へ接続します。

### OPA

Open Policy Agent です。本文を含まない正規化済み HTTP 判断入力を評価して結果を返します。Workspace ネットワークに接続せず、接続先への通信も行いません。

### upstream

許可済み request が最終的に選ぶ HTTP または HTTPS service です。HTTPS では Workspace 側の TLS connection が Gateway で終端した後、Gateway が別個に検証した TLS connection を upstream へ確立します。OPA は upstream connection を開きません。

### HTTP effect

Workspace Template ID、Workspace ID、ホスト、ポート、HTTP メソッド、パスと、限定された非秘密プロトコル情報からなる認可単位です。本文はポリシー識別情報ではありません。

### TLS connection A

Workspace から Gateway までの interception 対象 HTTPS connection です。Gateway は Workspace が信頼する Tobari CA に連なる証明書を提示し、policy 判断に必要な HTTP 属性を復号します。

### TLS connection B

Gateway から upstream までの、独立して検証される HTTPS connection です。connection A を Gateway が終端することは、最終 HTTPS destination へ plaintext HTTP を送ることを意味しません。

### Tobari CA

公開証明書が Workspace trust bundle に入り、Gateway が Workspace 側 TLS を終端できるようにする CA です。CA を信頼することは transport の前提であり、policy allow ではありません。certificate pinning を行う client は Gateway を迂回せず失敗します。

### fail closed

識別情報、ポリシー、スキーマ、状態、所有権の証拠が欠落・不正・曖昧・利用不能なとき、効果を拒否することです。リクエスト経路では未許可の接続先通信を行いません。

## Workspace 識別情報

### Workspace ID

一つの Workspace に対する安定した host-issued opaque ID です。project root そのものではなく、Workspace request header から authority として受理しません。内部の永続化と enforcement protocol では同じ値を schema-V1 `project_id` として保持します。

### Workspace Template ID

一つの Workspace Template に対する安定した host-issued identity です。変更可能な表示名や current Workspace Template marker とは別物です。

### Context ID

一つの Project root と Workspace Template の binding を表す安定した host-issued identity です。Policy Memory を所有し、Workspace Template ID と Workspace ID のどちらとも異なります。

### Workspace principal

専用ネットワーク上のカーネル観測エンドポイントから Gateway が導出する、Context ID と Workspace ID の信頼できる組です。ポリシーの範囲を決め、リクエストヘッダーでは置き換えられません。

### principal registry

正確な Workspace source endpoint、Gateway endpoint、専用 network を Context/Workspace identity に結び付ける host-owned mapping です。Gateway はこの directory だけを read-only で受け取ります。凍結した private compatibility field は旧 wire label を保持する場合がありますが、公開 alias ではありません。caller が与える `X-Tobari-*` text は registry authority を置き換えません。

### 専用 Workspace ネットワーク

一つの Workspace 用 Docker 内部ネットワークです。作業コンテナと Gateway のインターフェースだけが参加します。Workspace は OPA、別 Workspace、通常の外部ネットワークへ参加できません。

## ポリシー

### baseline deny

allow rule が一致しないときの既定の policy result です。ほかの条件が有効なら、秘密情報を含まない learnable evidence を生成できます。学習済み exact deny entry そのものではありません。

### learned allow

一つの Workspace Template、Workspace、host、port、method、path effect に対して明示的に有効化された exact rule です。信頼するホストでレビューし、完全な policy validation と atomic activation が成功した場合だけ authority になります。

### learned deny

明示的に有効化された exact denial です。baseline default と異なり、learned rule inventory に現れ、選択した exact decision として reset できます。deny は allow への途中状態ではありません。

### policy candidate

拒否の証拠から折りたたんだ提案です。権限ではなく、自動変更も行いません。

### policy review

信頼するホストが candidate を確認し、allow、deny、no action のいずれかを意図的に選ぶ flow です。Gateway の denial response はこの flow を案内するだけで、mutation authority を持ちません。

### policy activation

policy state を lock し、各 Context の Workspace Template baseline と Policy Memory、および全 Context の完全な projection を検証し、atomic publish と OPA reconcile を行う host process です。失敗時は known-good projection を保持または復元します。

### opaque reference

discover コマンドが生成し、対応する action が値を変えずに消費する検証済みの不透明値です。表示順やラベルから再構成しません。

### reset

選択した learned decision を一つ削除し、その exact effect を default deny へ戻す操作です。reset は allow ではなく、失敗した request を自動再試行しません。対象は opaque reference で binding されます。

## 認証と認可

### 認証

agent CLI が外部サービスへログインし、結果を Workspace home に保存することです。ログインの成功は通信許可を意味しません。

### 認可

OPA が一つの HTTP effect について返し、Gateway が強制する判断です。agent CLI のログイン状態とは独立しています。

### ツール固有の認証情報

agent CLI が所有するファイルや環境値です。Tobari はホストの認証情報を継承せず、値を OPA 入力と監査から除外し、許可後だけ元の値を転送します。同じ Workspace のプロセスから読めることは、Workspace の境界モデルに含まれます。

### Workspace 識別情報

policy evaluation に使う host-derived Context/Workspace authority です。agent CLI の login state とは独立しており、request header や credential file の内容では変更できません。principal registry と kernel-observed endpoint の exact join から導出します。

## 状態と公開契約

### authority envelope

installation の schema-1 Template、Context、Policy Memory、schema-3 Workspace、optional default Template selection を含む owner-only atomic file です。bare `status` は作成や修復をせずにこの authority を読みます。Docker state は observation であり authority ではありません。

### AppliedEntry

一つの exact Context、Template entry slice、Runtime revision に対する Workspace の last-successful receipt です。cluster、execution material、container、attachment が現在 ready であることまでは意味しません。

### aggregate policy projection

全 Context の Template baseline と Policy Memory から組み立てた完全なポリシー投影です。候補全体の検証とアトミックな有効化が成功するまで権限になりません。

### Catalog

`cli.Catalog` はコマンドパス、入力、効果、役割、出力、参照、変更、障害、復旧の公開正本です。ルーティング、ヘルプ、サイトの CLI リファレンスはここから導出します。

### command role

`utility`、`discover`、`act` のいずれかです。discover は opaque reference を生成できます。act は一つの reference-bound target または command-owned fixed target のどちらかだけを使い、表示ラベルから対象を再発見しません。

### operation effect

`read`、`create`、`write` のいずれかです。外部から見える全 operation が宣言し、unknown effect は fail closed です。read の表示から mutation を推測せず、write の完了後は confirmed outcome を保持します。

### mutation contract

外部 create/write より前に必要な intent、target binding、impact dimension と、実行後に必要な outcome authority です。target ref は exact input と一致し、出力が失われても confirmed mutation を retry permission に変えません。

### source snapshot

正本となる Gateway ソースツリーと、CLI がオーケストレーション用に埋め込むバイト一致のランタイム写しです。差分検査により二つ目の編集可能な実装になることを防ぎます。

## 共通の区別

| 混同しない語                       | 違い                                                                           |
| ---------------------------------- | ------------------------------------------------------------------------------ |
| Workspace と作業コンテナ           | Workspace は永続する論理状態、コンテナは交換可能な実行時リソース               |
| Context とクラスター               | Context は Project 固有の binding と Policy Memory、クラスターは共有の強制基盤 |
| 認証と認可                         | agent CLI がログイン済みでも OPA は HTTP effect を拒否できる                   |
| CA の信頼とポリシー許可            | CA は検査の前提、許可は一つの正規化された効果を通す判断                        |
| Workspace 識別情報とツールログイン | 前者はホスト由来、後者は agent CLI が Workspace home に所有                    |
| `exit` と `workspace delete`       | 前者はセッション終了、後者は論理 Workspace とホームの削除                      |
| タグとダイジェスト                 | タグは移動可能、ダイジェストは不変 OCI コンテンツの識別                        |

## 障害と制限

これらの定義はサポート対象の実装を説明しますが、脅威モデルを広げません。「信頼しない Workspace」は、選択した project root がその Workspace から保護されるという意味でも、明示的に許可した destination へ data を送れないという意味でもありません。

二つの語が衝突して見える場合、表示順や便利さで一方を authority にしません。規定する契約と exact boundary へ戻ります。trusted identity、schema、ownership、policy、credential state が欠落または曖昧なら fail closed であり、用語は代替 authority になりません。

## まとめ

Tobari は、永続する実行識別情報、ホスト設定、共有の強制、ランタイム、agent CLI 所有のログイン、ネットワーク許可を分離します。正確な境界には正確な用語を使ってください。

## 理解を確認する

<details>
  <summary>agent CLI がログイン済みなら、通信は許可されていますか？</summary>

いいえ。ログイン情報は Workspace home にあり、OPA が通常の HTTP effect を別に許可する必要があります。Gateway は許可後に元の認証情報を転送します。

</details>

<details>
  <summary>既定の Workspace Template を変更すると既存 Context や Workspace も移動しますか？</summary>

いいえ。既存 Context の Workspace Template ID binding と Workspace の Context ID binding は変わりません。既定値は bare root entry と bare `status` の選択にだけ使います。

</details>
