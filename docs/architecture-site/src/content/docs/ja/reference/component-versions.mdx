このページには、ドキュメントが参照する製品コミットで宣言された、ツール、イメージ、ランタイム API、CLI、スキーマ、ソースの識別情報を掲載します。表はリポジトリが管理するバージョン情報から生成し、同じ値を本文へ手作業で複製していません。

ソフトウェアバージョン、OCI セレクター、不変なダイジェスト、ランタイム API バージョン、JSON スキーマバージョン、ソースコミットは、それぞれ別の契約を識別します。以下の説明から、各行がどの種類の識別情報を示すか確認できます。

## 識別情報の読み方

| 種類 | 確認できること | 確認できないこと |
| --- | --- | --- |
| ツールバージョン | ビルド入力として選んだ Go、OPA、mitmproxy など | ローカルの Docker が現在保持するイメージの内容 |
| OCI タグ | 要求するレジストリチャンネル、または人が指定する選択子 | 不変性。タグは更新できる |
| OCI ダイジェスト | 選択する、内容アドレス方式のマニフェスト | ローカルランタイムが Tobari の互換インターフェースを満たすか |
| ランタイム API | 作業用イメージがサポート対象の Workspace インターフェースを宣言するか | イメージ内のすべてのパッケージが信頼でき、最新か |
| スキーマバージョン | 使用中の JSON 形式の正確な形 | 同じ番号を使う別の形式との互換性 |
| CLI バージョンとコミット | 実行ファイルに埋め込まれたリリースとソースの識別情報 | 現在のブランチ名や、ビルドされていないリリース |
| ドキュメントのコミット | このページを支えるリポジトリの時点 | その後に更新された `main` の状態 |

## リポジトリ内の正本

生成処理は、少なくとも次の正本を読みます。

- 選択した Go 言語バージョンとツールチェーンの契約を定める `go.mod`
- 共有コンポーネントの埋め込みバージョンと、固定したイメージの識別情報を定める `internal/infra/runtimeassets/assets/versions.env`
- `runtimes/base/` 以下にあるランタイムメタデータの正本
- 各 Go パッケージが公開するランタイム API とスキーマの定数
- 公開 JSON 出力のスキーマバージョンを定める CLI Catalog
- 公開 CLI バージョンをソースビルドまたはリリースへ埋め込む契約

生成結果は、正本とのずれを検査します。正本の値を変更してリファレンスを再生成しなければ、サイト検査は失敗します。製品バージョンの入力は、コミット済みのソースから読み取ります。コミットしていない途中の実験が、公開する識別情報の根拠へ紛れ込むことはありません。

## タグとダイジェストは同じではない

デフォルトのランタイムセレクターは次の値です。

<pre>
  <code>{componentVersions.runtime.default_selector}</code>
</pre>

これは更新可能な開発用タグです。デフォルトの取得元を指定するためには使えますが、不変な根拠にはなりません。Tobari が Context 管理のランタイムをビルドするときは、完成したローカルイメージを検査し、そのダイジェストを別に保存します。

OPA、mitmproxy／Gateway、Auth Broker、ベースイメージの共有基盤設定には、`versions.env` で宣言した値を使います。ダイジェストがある場合、それが不変なイメージ識別情報です。隣にある人向けのタグやバージョンは説明用です。

Gateway と Auth Broker には、ソースツリーの正本と、バイト単位で一致を検査する埋め込みソースもあります。ソースと埋め込み内容の一致は、ベースイメージのダイジェストとは別に検査します。レビュー済みのビルドには、両方の一致が必要です。

## CLI のバージョン表示

ソースからのビルドは `dev` を表示します。ビルドフラグでコミットを渡した場合は、そのコミットも表示します。リリース処理は、検証済みのリリース番号とソースコミットを埋め込みます。このページが報告するのは、ソースとビルドメタデータが実際に宣言する値です。Git ブランチ、タグのようなディレクトリ名、ドキュメントのバージョンからリリース番号を組み立てません。

実行中のバイナリを調べるには、次のコマンドを使います。

```console
tobari version
```

ソースへのリンクをローカル動作の根拠として使う前に、この結果と、ページ下部にあるドキュメントの生成元情報を比較してください。

## 障害と制限

- 正本の値がない、または形式が不正な場合、生成に失敗します。検証できていない値を `unknown` として表示しません。
- ダイジェストが確認するのは、選択した内容の識別情報です。ライセンスへの適合、ランタイムの正常性、ポリシーの正しさ、脆弱性がないことまでは証明しません。
- 宣言されたバージョンだけでは、ローカルの Docker キャッシュにイメージがあることを証明できません。起動前検査で必要なイメージを解決し、内容を調べます。
- ランタイムセレクターはビルドごとに変わる可能性があります。再現可能な根拠には、解決後のダイジェストを保存する必要があります。
- スキーマバージョンの意味は、対象となる形式ごとに異なります。製品のリリース番号として比較しないでください。

## まとめ

バージョンは互換性や名前付きリリースを表します。タグは更新可能な配布経路を選びます。ダイジェストは不変な OCI コンテンツを識別します。生成した表はこれらを区別し、すべての値をこのドキュメントが参照するコミットへ結び付けます。

## 理解を確認する

`runtime:latest` を不変な識別情報として扱うのは誤りです。

<details>
  <summary>OPA のソフトウェアバージョンで Gateway イメージを識別できますか？</summary>
  いいえ。別のコンポーネントであり、識別情報も別です。生成した表は、それぞれの正本から値を取得します。
</details>

<details>
  <summary>ソースからビルドした <code>tobari version</code> は通常何を表示しますか？</summary>
  `dev` です。ビルド時に値を渡した場合だけ、ソースコミットも表示します。リリースビルドでは、検証済みのリリース識別情報を埋め込みます。
</details>

<details>
  <summary>固定されたイメージダイジェストは、そのイメージが Workspace 用ランタイムと互換だと証明しますか？</summary>
  いいえ。Tobari はランタイム API ラベル、寿命管理の機能、ユーザー、エントリーポイントを別に検査します。
</details>
