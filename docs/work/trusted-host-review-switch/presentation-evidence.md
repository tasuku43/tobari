## Product compatibility decision

- Decision owner: Tobari maintainer
- Selected presentation: `Ctrl+]`, then `r`, opens same-terminal Trusted Host
  Review with Permission Inbox as the first source
- Compatibility rationale: follows the established local-command prefix
  pattern while avoiding tmux, Screen, Docker, and line-start-only SSH prefixes
- Schema/version impact: no machine-output schema change expected; root
  interactive help and terminal ownership change
- Rollout and rollback: pre-public; ship only after PTY evidence, otherwise
  retain separate-terminal review and remove the interceptor completely
- Relationship to the experiment outcome: product direction is accepted, but
  technical eligibility remains conditional on the PTY experiment

## Security and execution boundary

- [ ] Fixtures and evidence are synthetic and public-safe.
- [ ] Artifact paths are repository-rooted regular files reached without
      symbolic links.
- [ ] Any subprocess has fixed executable/argv, finite timeout, bounded output,
      private temporary storage, and no inherited secrets.
- [ ] Network and tools are disabled unless an accepted local Docker/PTTY
      observation requires and documents them.
- [ ] Live terminal evaluation is separate from deterministic `task check`
      fixtures.
